# 現行のまま続ける、一件

架空の備品引継ぎの例です。以下は例の中の設定で、実案件の観測や製品の実績ではありません。

「引継ぎ済みのはずなのに、相手には届いていない」という話が出ました。

| この一件で確かめたこと | まだ分からないこと |
| --- | --- |
| 引継ぎ記録には更新時刻と次の担当者が残っていた。 | 他の引継ぎでも同じことが起きているか。 |
| 受け手は別の保管場所を見ていた。同じ記録を一緒に開くと、内容を確認できた。 | 同じ場所を確認すれば、次の一件も届くか。 |

この一件だけでは、受渡しの手順そのものが原因とは決められません。そこで、**今の手順を続け、次の一件で受け手が同じ記録を見つけられるか確かめる**、と暫定的に決めました。見つからなければ、取り組みを決め直します。

同じ記録を一緒に開いたのは事実確認です。通知方法・役割・承認手順を変える判断は、まだしていません。続ける理由と未確認点を「取り組みの判断」に残します。

1. [入口の問い](README.md#uc-decide)から「取り組みを決める」へ進みます。
2. 関係図の「業務モデル」アイコンを開き、比較の前提を確かめます。
3. 用語集の「取り組みを決める」から同じ関係図へ戻ります。
4. 業務アイコンから手順へ進み、「続ける・見送る」の分岐を確かめます。
5. 「この仕事の関係に戻る」から関係図へ戻り、「いまの問いに戻る」で出発した問いに帰ります。

この図が描くのはfdeを育てる仕事です。架空のチームの例は、その判断と往復を考える練習です。顧客業務へ役割をそのまま当てはめることや、改善効果を実証するものではありません。
