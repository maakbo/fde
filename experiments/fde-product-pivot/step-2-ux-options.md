# fde Step 2｜使う人と場面から組み直した10案

設計対象は **`maakbo/fde` リポジトリ自体**。合意済みのStep 1はそのまま。どれも「話・現物から要素を拾い、名前、役割、関係、流れ、具体／抽象の粒度を動かす → 何を変えるか選ぶ → 小さく試す → 人が結果を見て判断する」を残す。違うのは **誰のどの瞬間を最初に助けるかと、何を見せればまた使いたくなるか**。以下の場面は比較用の仮例であって対象業務の固定ではない。作者は初期検証者であり、ニーズの実在や他の組織への一般化は未検証。Step 3の配置・ラベル確定、試作、実運用はこの文書の対象外。

## 見比べる

| 案 | 主に使う人・開く瞬間 | 最初に見せるもの | 何が起きたら選ぶ価値があるか |
|---|---|---|---|
| 1｜まだ言葉にならない | 自分の仕事を見直す人。違和感はあるが課題名がない | 一文で始める短い対話案内 | 違和感の正体が自分の言葉になる |
| 2｜手元の現物から | 実務担当。既存手順と実際が噛み合わない | 現物の一箇所から始める案内 | 実態と記述の差を示し、一つ試せる |
| 3｜見取り図を組み替える | 仕組みを組み立てる人。既存図が複雑化 | 編集できるモデルと粒度の切り替え | 関係や境界を直せ、試す箇所が変わる |
| 4｜違う見方を並べる | 話し合いを支える人。次の会議まで時間がない | 同じ対象の複数の見方 | 見方を消さず暫定判断できる |
| 5｜目指すことから逆にたどる | 方向を決める人。指標や施策が目的から離れた | 目的と日々の仕事のつながり | 大事にしたいことが次の仕事の選択を変える |
| 6｜いちばん不確かなことを試す | 小さな改善を任された人。時間や資源が少ない | 検証したい問いと小さな試行の型 | 結果が継続・再試行・見送りの判断を変える |
| 7｜途中の仕事を受け取る | 次の担当者。以前のチャットがない | 特定版の成果リンクと再開欄 | 推測や再説明なしで安全に続きを始められる |
| 8｜AIとどこまで分けるか | AIとすでに協働する人。丸投げも確認疲れも避けたい | 一作業の委任と判断境界 | 人が価値判断に戻れ、AIは範囲内で働ける |
| 9｜似た実践から始める | 初めて伴走する人。用語・手順をまだ知らない | 詰まり方で選べる短い作例 | 似た点だけ借り、違う条件は見落とさない |
| 10｜使った後に道具を育てる | 継続運用・再利用を担う人。別の条件でまた困った | 試行後の観察と、型への戻し方 | 現場固有の違いを守り、一つの学びが再利用できる |

## 1｜まだ言葉にならない
- **戦略：** 自分の仕事にモヤモヤはあるが、問題とも解決策とも言い切れない人。必要なのは正しい業務名を選ぶことではなく、何に引っかかっているかを見つけること。fdeは整理の前から使える入口を持つ。
- **要件：** 口語一文と具体的な一場面。観察、解釈、次の問い、最小のモデルと試行案。最初から所定フォームを要求しない。
- **構造：** 「ここで毎回止まる」→ 直近一回を対話でたどる → 名づけて関係を描き、違う粒度も試す → 一箇所を試して前後を見直す → 続けるか決める。
- **骨格：** READMEの入口は一文を渡す例と返ってくる下書きを先に。既存テンプレートは対話が必要性を示した地点で開く。
- **表層：** 普段の言葉、一問ずつ、余白。未整理の言葉は訂正前後を見分けられるようにする。
- **取引・条件：** 話しやすいが、既に対象が定まった人には遅く感じる。事実を創作せず一場面を聞けること、手元の成果から直接入れる逃げ道が必要。

## 2｜手元の現物から
- **戦略：** 既存の文書・チケット・表を扱う実務担当。説明を作り直さず、現物に現れたズレを確かめたい。fdeは現物と実際の仕事を行き来する作業台になる。
- **要件：** 参照できる対象と版、箇所、現物の記述と実際にしたことの区別。見えない部分は未確認にできる。
- **構造：** 「この一節だけ、実際と違う」→ 許された範囲で該当箇所を参照 → 誰が何を渡す関係かを言葉と図で直す → 一つの変更を試す → 現物へ確認結果を返す。
- **骨格：** 「手元の成果を使う」と対象・版の欄を入口に。現物／実際／影響の並びを成果内に置き、根拠はリンクで開く。
- **表層：** 引用と自分たちの解釈を明確に分け、差分は色だけに頼らず文字で表示。
- **取引・条件：** とっかかりが具体的だが、現行資料だけを真実と見なしやすい。共有許可と現場確認が条件。資料がない人は口語から入れる。

## 3｜見取り図を組み替える
- **戦略：** 複数の仕事や役割をつなぐ設計担当。図がきれいというだけでなく、見る問いに合う粒度を選びたい。fdeは構成と名前を動かせるモデルの工房になる。
- **要件：** 一つの問い、対象・境界、元の言葉と正規化した名、関係を示した理由、上下の粒度へのリンク。読み手向けモデルと作業記録を分ける。
- **構造：** 「同じ関係図で二つの話をしていた」→ 目的の違うビューへ分け、捨てない要素を判断 → 試す受け渡しを一箇所選ぶ → 結果で関係や粒度を戻して直す。
- **骨格：** 最初に編集元Markdown、図、短い読み方。その直下に「どの問い／どこまで／詳細を開く」。六業務の一覧は二次導線。
- **表層：** 既存の小さなアイコン・余白・短いラベル。図が読めない環境には同じ意味の要旨を添える。
- **取引・条件：** fdeらしい造形と思考が前面に出るが、図を整えること自体が目的化しやすい。実際の問いと試行へ戻る導線、Mermaidが苦手でも意味をレビューできることが必要。

## 4｜違う見方を並べる
- **戦略：** 会議で判断を支える人と、異なる制約で仕事をする関係者。短時間で全員を一致させるのでなく、違う見方が何に影響するかを知りたい。fdeは共通の検討素材をつくる。
- **要件：** 同じ対象・版に対する複数の見方、各根拠と影響、共通部分、確認先、暫定判断、再確認条件。
- **構造：** 「この仕事を終えた」の意味が二者で違う → 見方を並べる → 役割・受け渡しの境界を直す → 差が出る一場面を小さく試す → 暫定判断を見直す。
- **骨格：** 会議用の成果リンクから開き、「同じところ／違うところ／今日決めること」を先に。原資料を触れない人でも意味を確認できる。
- **表層：** 勝ち負けを示す赤緑ではなく、同じ書式と対称な余白。見方が違う理由を短く併記。
- **取引・条件：** 話し合いの質が前面に出るが、一人で探究したい場合は重い。発言・引用の範囲が許され、当事者が訂正できることが前提。

## 5｜目指すことから逆にたどる
- **戦略：** チームの方向はあるが日々の手順に反映されていないと感じる人。目的を掲げるだけでなく、今日の仕事の選択につなげたい。fdeはビジョンと仕事のあいだの関係を見直せる道具になる。
- **要件：** 大事にする目的の一文、変えたい具体場面、目的と役割・作業の対応、反対例、確かめたい変化と副作用。
- **構造：** 「判断する人が自然に力を出せる」→ どの場面でそれが出ないか下りる → 関係と境界を描く → 小変更を試す → 日々の観察から目的の言い方にも戻る。
- **骨格：** 最初に目的と一場面を対にして表示。「目的から作業へ／現場から目的へ」の双方向リンク。
- **表層：** 抽象語の隣に「例えばこの場面」。説明に重きを置き、指標を成果の唯一の代替にしない。
- **取引・条件：** maakboの価値観に深くつながるが、目的の言語化を先に要求しすぎると入りづらい。違和感や現物側からも逆にたどれ、目的を関係者が修正できることが前提。

## 6｜いちばん不確かなことを試す
- **戦略：** 改善を任されたが、大きな作り込みの時間がない人。何を作るかより、判断を変える不確かさを一つ早く確かめたい。fdeは図や説明を試行の設計につなぐ道具になる。
- **要件：** 問い、現行モデルと変更仮説、対象版、観測条件、許可、例外、中止条件、結果と判断の区別。
- **構造：** 「案Aを選ぶと境界で詰まらないか」→ モデルで変わる関係を指す → 安全な小試作 → 通常と別条件で観察 → 理由を添えて継続・再試行・見送り。
- **骨格：** 最初に「確かめたいこと／今できること／まだできないこと」。根拠図と既存の試行型を近くに置く。
- **表層：** 「予想」「観察した」「決めた」を見出しで分け、未測定を空欄やゼロへ変えない。
- **取引・条件：** 実装の量に流れにくいが、問題がまだ曖昧な人へは早すぎる。試行前の条件と権限確認、観測からモデルへ戻ることが条件。

## 7｜途中の仕事を受け取る
- **戦略：** 別担当、日を空けた自分、文脈を持たないAIのどれかが引き継ぐ場面。判断の背景を再聴取せず、誤って実行もしない道具が欲しい。fdeは会話より長く残る成果を使いやすくする。
- **要件：** 一意の成果と対象版、判断・理由、未決・確認先、今できること／止めること、結果へのリンク。既存Issueや文書を複製しない。
- **構造：** 成果の特定版を開く → 既知／未決／許可を読み分ける → 理解の違った関係を差分で戻す → 次の小試行または確認へ → 同じ識別子で継ぐ。
- **骨格：** READMEを通らなくても成果リンク先の上部で再開できる。理由・結果・次が先、詳細は下か参照リンク。
- **表層：** 先頭は短い受け渡し、日本語の状態語と版情報。運用者向け記録と読み手向け図は混ぜない。
- **取引・条件：** 続きが見えるが、記録負荷で会話の勢いを削ぎ得る。既存成果の使い回しと、別担当者が文脈を持たず再開する実地比較が必要。

## 8｜AIとどこまで分けるか
- **戦略：** AI活用の経験があり、任せられる準備まで全部確認して疲れる人。AIの力を借りつつ、意味や権限の判断は手放したくない。fdeは委任の適切な粒度・境界を見つける道具になる。
- **要件：** 目的、対象、期待成果と根拠、AIで進めてよい準備、止めて確認すること、独立した受入条件。
- **構造：** 「この一作業を任せたい」→ 人／AI／システムの関係と例外を描き直す → 許可範囲で試す → 人が証拠と抜けを確認 → 境界を狭めるか広げるか決める。
- **骨格：** 委任前の一画面相当で「人の判断／AIが進めてよい／止める」を対等に置く。詳しいSkillはその後。
- **表層：** 「提案」「承認」「実行済」の語を固定。判断には短い理由と根拠リンク、長い作業ログは後ろに。
- **取引・条件：** AI利用の実際の痛みに効くが、AI化そのものを目的に見せやすい。人だけで進める案と比較し、承認を独立して識別できることが条件。

## 9｜似た実践から始める
- **戦略：** 初めて務める支援役。六業務の分類や個々のSkillを知らなくても、自分に似た詰まりの進め方を掴みたい。fdeは手本をコピーするのでなく条件を読み替える見本帳になる。
- **要件：** 短い汎用作例、前提・例外、借りる箇所／自分は違う箇所、適用先の型のリンク。
- **構造：** 「手戻りの理由をうまく話せない」に似た合成例を開く → 例と自分の違いから名前・関係を組み替える → 試行を設計し直す → 適用の条件を記録する。
- **骨格：** 「検討が止まる／途中を受け取る」等の利用者の言葉で例を探せる索引。作例冒頭に条件と適用しない範囲を置く。
- **表層：** 短いカード相当の見出しと「架空例」「未測定」の明記。例示値は実績に見せない。
- **取引・条件：** 具体例で迷いが減るが、テンプレをそのまま当てる危険。複数の異なる作例と、借りない部分を説明できることが必要。

## 10｜使った後に道具を育てる
- **戦略：** 現場で動かしながら仕事や型を育てる人。導入時の設計に縛られず、繰り返し起きた違和感を次に活かしたい。fdeは成果だけでなく道具そのものを少しずつ育てられる。
- **要件：** 実行後の観察、対象版と条件、モデルの差分、案件固有／再利用候補の分離。型を直すか判断する受入条件。
- **構造：** 「別の条件で同じ受け渡しがまた止まった」→ 元の判断と現行観察を比較 → 要素・名前・粒度を直して再試行 → 複数で確認された学びだけを汎用化候補へ戻す。
- **骨格：** 既存の評価・運用ページや成果リンクから「結果から見直す」に入る。成果側に元の判断と観測、公開側には条件付きの学びだけを置く。
- **表層：** 「今回の事実」「別の場面でも使えそう」「まだ仮説」を文字で区別。成功談に整えず変えた理由を見せる。
- **取引・条件：** Step 1の「育てる」を日常化するが、初回に見ると実感しにくい。複数回使えて、固有情報を公開せず意味を取り出せることが前提。

## 選び方

一案ごとに「何が最初に欲しいか」「この案の失うものを許せるか」を見る。複数が近ければ **入口の主役を一案、そこから欠かせない副線を一案**選ぶ（たとえば「1から入り3で手を動かす」と「3から入り1を困ったときだけ使う」は違う）。役に立つ十機能の採用投票にはしない。どの案も、初回の想像と実際の行動、その後でモデルと判断が変わったか、別日に自らまた開いたかを現行と比べて検証できる。現時点では判断材料であり、実装・公開・次工程への許可ではない。

## 同じ場面で、入口の違いを比べる

架空の同じ仕事で、引き渡す側と受け取る側が「確認済み」を違う意味で使っているとする。どれも最終的にはこの違いと試す案を扱えるが、**最初の5分で手にするもの**が違う。題材を固定する意図はない。

1. 相談起点：直近で止まった一回を話し、確認を求められた瞬間を切り出す。
2. 現物起点：既存資料の「確認済み」に印をつけ、記述と実際を並べる。
3. 図起点：同じ矢印で表した二つの受け渡しを分け、どこに境界があるか直す。
4. 関係者起点：二人の意味を並べ、どの状態を次の判断の前提にするか話し合う。
5. 目的起点：何の安心のための確認かに戻り、日々のどの仕事で確かめるか選ぶ。
6. 試行起点：状態を二つに分けた小さな作例を試し、受け渡し時の聞き返しを観察する。
7. 再開起点：成果リンクから経緯を読み、「次の担当がまだ決めてはいけないこと」を確かめる。
8. AI協働起点：二つの意味を比較する下準備はAIに任せ、確定と適用範囲は人が決める。
9. 作例起点：違う意味を分けた架空例を読み、自分の仕事に移せるところだけ借りる。
10. 運用起点：試した後にもう一度詰まった箇所を読み、前提か型のどちらを直すか決める。
