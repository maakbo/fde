## 今回反映した選択

- 情報：Bの折り返し付き紙。丸い抽象記号より四角が描きやすいという意向を反映。
- システム：Aの短い状態表示付き枠。Bの上帯は画面の印象が強いため使わない。
- 業務：Bの横長楕円を維持し、縦半径だけ `5.55 → 6.00` にする。横半径9.3は同じ。30px表示で全高が約1.13px増え、上下へ約0.56pxずつ広がる、小さな調整。
- 人：Bを土台に、頭を `rx3.6 / ry3.9` へ少し大きく、肩幅を16から13.2へ小さくした試案。顔パーツは加えず頭の輪郭だけで表す。肩の山も少し浅くし、頭に対して下の重みを抑える。
- 判断：Bの形を維持。
- AI：眠って見える横棒の目を、丸端の短い縦線に変更。今回、頭の角丸だけ `1.1 → 1.7` に調整。
- リポジトリ：ユーザーが候補2・枝分かれを選択。フォルダを外し、縦2点＋右上1点の丸と線へ変更。丸の半径を2.90から2.30へ約21%小さくし、線の接点を丸の縁へ合わせる。その後、違和感の原因として挙がった枝の曲線を、幹の途中から右上の丸の左下の縁へ向かう斜めの直線に変更。その後「上から下」を選択。上丸(8,4.8)、下丸(8,18.5)、右丸(17,11.65)として右丸を中間高さへ置き、上丸から後続2丸へ直接つなぐ。丸の半径2.3と線幅1.15は維持。上下の継続線は比較候補で、ユーザーが「追加線なし」を選び、全12セットも追加線なしで確定。
- 情報の追加試案：紙の外周3隅を小さく丸め、折り返しの内角もわずかに丸める。紙の斜めの角と折り返しの意味は残す。
- 線幅：全12種類を `1.35 → 1.15`、約15%細く統一。初回A/B比較の線幅は履歴として維持。
- 端末：タブレットの縦横比を約0.76へ整え、角丸1.7。スマホの角丸を2.0、PC画面を横長にして角丸0.95。iPad・iPhone・MacBookのように柔らかな角を意識しつつ、ロゴ、ノッチ、ボタンは追加しない。
- 残り7種類：四角と短い線を土台に、同じ細線と輪郭の設計で追加。人の頭・業務・外部サービスの雲には、意味を保つため曲線を残す。

「初見の分かりやすさ」だけでなく、**自分で素早く描き直せること**を設計基準にしました。装飾、文字線、メーカー固有の特徴、端末のボタンは足していません。[目・線幅・端末の変更前後](detail-refinement.png)で差を確認できます。手書き時に角の丸みや曲線を厳密に再現する必要はありません。

リポジトリの枝はGitの詳細な履歴図ではなく、履歴と分岐を表す最小の目印です。一般的なフローにも見えるため、下ラベルで意味を確定します。外部サービスは四角へ置き換えるとシステムと取り違えやすいため、雲の輪郭を保ちました。タブレットは画面を持つ端末、システムは短い状態表示を持つ箱として区別します。AIは人と区別するため、四角い頭とアンテナを残します。

## 共通仕様と制作

全原本は24×24の正方形viewBox、透明背景、表示線幅1.15相当、round cap / join、塗りなし。大きさを拡縮するgroupは `stroke-width = 1.15 / scale` と逆補正し、実際に表示される細線の太さを維持します。`currentColor`に加えてSVGルートで `color:#25231F` を明示し、単独の画像として表示した場合も比較シートと同じneutral inkになります。

Lucideその他ライブラリのパスをコピーしていません。基本図形と本セット用の独自座標で制作しています。ファイル名は置換箇所を対応させやすいよう既存名と互換にしました。`server.svg` という名前でも、サーバーの積層図にはしていません。

各記号の描き方を[手書きの順序](handwriting-guide.md)で1〜3ステップに整理しました。「ステップ」は形を作る動作の単位で、一筆の回数ではありません。手書きの所要時間やユーザー本人の再現性は、まだ実測していません。

## 時間方向の追加比較（上→下を選択済み）

ユーザーが「上から下、あるいは左から右」と示した時間の読み方に合わせ、[時間方向の比較](repo-timeline-options.png)を作りました。上→下は先の点が最上、左→右は先の点が最左です。後続2点は時間軸上の別位置に置き、2本の直線を祖先の丸の縁から直接つなぎます。幹の途中に、丸で示されない分岐元は置きません。

原本は `candidate-repository/top-down.svg` と `left-right.svg`。丸の半径2.3、線幅1.15、透明背景を維持。この比較は方向選択前の履歴です。その後、上→下が選ばれ、右丸を中間の高さへ置いた基本案を全12セットとHTMLへ反映しています。

推奨は上→下です。先の丸が一番上にあり、その後に枝分かれする読み方が縦の履歴として伝わります。左→右は横にたどりやすい案です。どちらも下ラベルと組み合わせる概略記号で、実際のGitコミット時刻や間隔を表す図ではありません。

両候補のXML、丸の縁で止まる2本の線、時間軸方向が祖先→後続で単調に進むこと、後続2点が同じ時間位置に揃わないことを確認しました。32px実寸で点と直線を目視確認済み。制作・MITの記録へのリンクは上記のままです。
