# AI利用の条件を判断できる相談材料を作る

成果は[共通の成果形式](../../../guides/field-work/references/artifact-contract.md)と、この作業が参照する型の必須項目を保つ。既存記録への追記でも同じ項目を引き継ぐ。

## 入力

対象業務/利用目的、入力から結果利用までの一件、既知の情報経路・環境・許可・契約/方針の根拠。
既存の委任/接続/失敗記録を再利用し、不明を埋めるために機微情報の原本・資格情報を集めない。

## 手順

1. 誰の何の仕事を変え、調査/下書き/確定/送信/公開/更新のどこまで任せたいかを置く。試行と本番、開発支援と製品のAI機能を分ける。
2. 必要な情報の種類と範囲を、原資料→検索/索引→モデル入力→出力利用→ログ/保管/削除までたどる。接続要件があれば再利用し、送信先/運用主体/利用地域/二次利用が不明な箇所は不明とする。RAGだから外部送信、社内環境だから外部送信なしと決めない。
3. 利用目的と対象地域、個人情報や機密/契約上の制限、原資料の利用・複製・参照、生成物の権利/公開を確認論点にする。氏名置換を匿名化・入力許可の証明にせず、創作への関与と第三者権利の侵害も別にする。法的結論を作らず、必要な一次情報と担当への問いを置く。
4. 法令/公的解説、契約/サービス条件、社内方針、今回の操作許可を分け、出典/版/確認日/適用条件と決定権者を記す。時点依存の主張は採用前に一次情報へ照合し、未提供の契約や社内決定を公的ガイドだけで代替しない。
5. 相手に合わせて、事実→業務上の影響→選択肢→決めてほしい範囲と問いを短く返す。法務へは目的/地域/情報利用/権利・契約条件、セキュリティへは経路/ID権限/保存/停止、業務責任者へは任せる操作/確認負担/代替を示す。部署が存在するとは仮定せず、役割・決定者が不明なら確認先の探索案まで。
6. 実回答・演習条件・提案・未回答を分け、許可/禁止/条件付き/判断待ちと対象範囲を記録する。一人の回答や人のレビューを、他の領域の承認や法的責任の移転へ広げない。相談文案と実送信は別で、このSkillは送信・契約・運用開始の許可を追加しない。
7. 判断済みの条件をdefine-delegation-boundaryとdesign-risk-responseへ、実態/更新はreview-operating-inventoryへ渡す。方針→実行制御→必要最小限の証跡と試行をつなぎ、未決に依存する送信/公開/本番化は進めず、許可内の架空例や設計下書きは続ける。

## 成果と完了

[既存の失敗・対応記録](../../../templates/field-work/risk-and-operation-record.md)の相談欄を必要な部分だけ使う。
一件の経路/操作/事実と不明、根拠/判断者/選択肢/問い、実回答と次の担当が追える。相談材料の完成を法令適合や開始許可にしない。
適用条件は[方針を操作と確認へ変える](../ai-pilot-evaluation/references/governance-and-use.md)を必要な箇所だけ読む。
