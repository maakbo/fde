# 取得した根拠と回答の主張を別々に照合し、原資料・抽出・検索・入力受渡し・生成のどこを直すか決める

成果は[共通の成果形式](../../../work/references/artifact-contract.md)と、この作業が参照する型の必須項目を保つ。既存記録への追記でも同じ項目を引き継ぐ。

## 入力

対象の判断と質問、許可された原資料/版、既存の参照単位・属性・試行結果があればその記録。
不足があっても使える部分の下書きを返し、権限・原文・実測の不足を埋めない。

## 手順

1. 対象業務/質問と参照可能な資料の集合・版・権限、期待根拠/必要条件/回答の留保を確認する。期待が未決なら確認待ちを残し、正解率を作らない。
2. 直接参照、完全一致/キーワード、ベクトル/併用など必要な方式を比較候補にする。問合せの変換・分解や検索先の振分けでは、元の対象/条件/権限を保つ。方式名だけで優劣を決めない。
3. 同じ質問で取得したID/版/位置/順位/条件を記録し、期待する根拠と照合する。存在しない/未許可の根拠と、存在するが検索で漏れた根拠を分ける。近さや順位を正しさにしない。当該判断で参照不可の対象外/旧版や未許可資料が混ざったら回答入力へ渡さず、取得側の参照制御の問題として返す。未許可本文を評価記録/入力へ転記しない。
4. 検索候補から実際に回答入力へ渡った断片を追跡する。並べ替え/絞込み/上限/切詰めで必要な例外が消えていないかを確認する。ログがなければ検索と生成のどちらかに断定しない。
5. 回答の主張/条件/留保を実際に渡った根拠へ照合する。必要時はverify-output-evidenceの確認結果を再利用し、同じ主張の照合を繰り返さない。原資料にあるが入力にない条件と、入力にあるが回答から落ちた条件を区別する。
6. 原資料の不足/版・許可、抽出/参照単位、質問/検索先、順位/入力受渡し、生成/解釈のどこへ戻すかを観測から選ぶ。影響が不明なら仮説を分け、小さな一変更で同条件と別条件を再試行する。
7. 件数/率を出す場合は評価集合、期待根拠の分母と判定規則を記す。検索の網羅性、回答の忠実さ/必要条件の充足、現場効果を別に返す。架空の検索ログや手作りの回答照合を実モデル/本番の精度と呼ばない。

## 成果と完了

[既存の記録](../../../templates/knowledge-use-brief.md)を必要な箇所だけ使い、同じID/版/未決を引き継ぐ。
質問→期待根拠→取得候補→実際の回答入力→主張の判定→修正先/再試行がつながる。測っていない段階と原因未確定を明記する。
原理と選択肢は[知識を探して使う判断](../knowledge-stewardship/references/knowledge-and-retrieval.md#ragを準備と利用に分ける)の該当箇所だけ読む。
