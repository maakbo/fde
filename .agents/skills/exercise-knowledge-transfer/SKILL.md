# 知識記録を別の人や別条件の一件へ適用し、誤りを元の知識へ戻す

## 入力

対象業務/判断、許可された事例や資料、知識の候補と所有者について分かること。
不足を明記し、今ある情報から返せる仮説/下書きを進める。録音/全会議収集/個人情報原本の保存を開始条件にしない。

## 手順

1. 対象知識のID/版/適用範囲/許可と、誰が何をできるようになるかを置く。経験者の確認が未完なら仮説を試す演習として分ける。
2. 通常、条件不足、適用外/例外などを選び、期待する根拠と判断を可能なら別に用意する。完成解答を実行役へ渡して丸写しを試行としない。
3. 共有先と範囲が許可されている場合に、次の人/別の実行役へ必要最小限の知識と入力を渡し、何を見てどの条件を適用し何を返したかを残す。共有が未許可なら、許可された架空事例による演習か実施案までに留める。別役を使わなければ独立試行と呼ばない。
4. 根拠/条件/判断/操作許可を照合し、正解率だけでなく、なぜその判断になったかと未確認の扱いを見る。
5. 誤りを事実/条件/手順/情報不足/検索/解釈/権限へ切り分け、最も近い知識・原資料・手順へ戻す。モデルの変更だけを繰り返さない。
6. 訂正版と同じ条件、さらに別の一件を試し、解消と未決を記録する。実装していない索引/配備更新や現場効果を実証済みにしない。
7. 所有者、次の更新条件、利用者の訂正経路を残す。原資料や所有者の確認なしに規則を拡大しない。

## 成果と完了

[作業の記録](../../../templates/field-work/knowledge-transfer.md)を必要な範囲で使う。
知識の版→適用事例→結果/理由→照合→修正/再試行/未決が追え、実演習と現場の効果を区別できる。
背景の区別が必要な時だけ[知識を使える形にする判断](../../../guides/field-work/references/knowledge-in-work.md)を読む。
