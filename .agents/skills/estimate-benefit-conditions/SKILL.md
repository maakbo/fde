# 業務の変更から余力・品質・利用体験・実際の支出減へつながる条件を見積もる

## 開始入力

現行の件数/全工程時間/品質、変更案、人の確認/修正/支援、利用範囲、費目や受益者についての説明。
不足があっても、明示された情報から作れる仮説/下書きを先に返し、未確認を分ける。

## 実行

1. 誰のどの仕事を何のために変えるかと、効果が生じる対象/期間/件数を確認する。観測と見込みを分ける。
2. 現行と変更後で開始/終了を揃え、実行だけでなく確認/修正/例外/支援を積む。各時間に人の作業/AI処理/待ち/支援などの種別と担当を付ける。種別不明を人手へ算入しない。待ち時間と人の作業時間は重複なく別に追う。複数担当の作業時間と、開始から終了までの経過時間は別の集計にする。
3. 件数×全工程差から余力を計算し、他者へ移った負担を控除する。月単位の支援時間を案件一件の経過時間へ足さない。時間種別が不明なら条件付きの投入時間合算までとし、現時点の人手余力/経過時間短縮/工数価値を確定しない。利用がない仕事の効果や、削減できない固定時間を含めない。悪化も符号付きで返す。
4. 余力×時間単価は工数価値の参考換算と記す。残業費/委託契約等の費目がいつ減るか、誰が変更するかの根拠がなければ現金削減は未成立。明示的に固定ならその範囲で現金削減なしと区別する。
5. 品質、利用者/担当者の体験、余力の使い道を、誰の観測/比較条件で確かめるかへ置換。便利になるという説明だけで効果実測としない。利用不安/確認負担/副作用も残す。
6. 利用減や確認/修正増の条件を試し、どの前提で期待効果が消えるかを示す。売上/利益に換算するなら因果と費用/重複/時期を別に確認する。
7. 費用と同じ対象/期間で比較できる効果だけを受渡す。現金と工数価値、実測と仮定を別欄のまま、次に確かめる指標/担当/未合意を返す。

## 成果と完了

[総費用と効果の効果欄](../../../templates/field-work/cost-benefit-record.md)。投資判断の比較は別作業へ渡し、この作業だけでGoを出さない。
全負担を含む差分、受益者、効果の種類と成立条件/時期/未確認が追える。時間換算を支出減や実績と呼ばない。
入力/前提が変われば該当行へ戻す。許可や実回答が必要な事項をagentが代作しない。
