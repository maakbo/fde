# 仕事に合う自動化の形を比較して選ぶ

## 入力

対象業務/現行と変更案、望む成果と成功条件、手順と例外、根拠/利用操作/許可、既存の試行結果と制約。
既存記録のID/版/未決を引き継ぐ。今ある条件から比較案を返し、実装/実績/決定を代作しない。

## 手順

1. 作成から確認/修正/受渡しまでの一件を保ち、どこが問題かを絞る。内容の品質、毎回の指示、転記/接続、待ち、途中判断、確認負担を分け、製品利用者の業務と開発チームへのAI支援を混ぜない。
2. 操作ごとに、起動は誰/何か、順序と分岐は固定か途中で選ぶか、参照と状態/外部作用は何か、提案/確定/実行の許可は誰にあるかを分ける。チャット/定時/接続/承認の有無や製品名だけで自律性を決めない。
3. 人の現行/決定的な規則や通常ツールも含め、関係する候補を比較する。都度相談、用途別の指示/知識、固定の手順/分岐、範囲を限定した計画/実行は組合せられる。全候補の実装や、全段階を順に経験することを開始条件にしない。
4. 各候補に、減らす不確実性/残る負担、必要な根拠・接続・維持、人の確認能力/時間、誤りの影響・検知/復旧、費用/遅延を対応付ける。既存の費用/効果/リスク記録を再利用。件数の多さ、低リスクの呼び名、修正可能性や平均精度だけで自動実行を許可しない。
5. 目的を確かめられる小さな形を選び、選ばない案の理由と見直し条件も返す。対話支援を必須の入口にせず、転記/待ちが主因なら許可された限定接続を試す案も比較する。動的計画が要るなら、途中結果で何を選ぶ必要があるかを示し、許可道具/対象/反復・時間・費用の上限/完了/中断/人への返却を具体化。不明な上限は未決のままにし、無制限の実行を前提にしない。
6. 自動で進める操作、人が確認して進める操作、情報不足で戻す操作、許可外で行わない操作を分ける。自信度だけで経路を決めず、根拠/矛盾/許可/影響を照合する。既存define-delegation-boundaryの契約を使い、レビュー者の原資料アクセス/技能/時間/拒否・修正権/不在時の戻り先を確認する。
7. 最初の試行に、対象/対象外、許可環境、受取る成果、品質/使い方/全負担の観測、停止/手動継続、担当/判断時点を置く。通常/根拠不足/許可外と、自信度と実際の条件が逆になる例を追う。設計の机上追跡、決定的な制御の実行、モデル評価、現場効果を区別する。
8. 比較と選択を同じ記録へ返す。未合意の判断は判断者へ、許可済みの準備は進める。委任の詳細はdefine-delegation-boundary、起動はdesign-trigger-contract、役割はpartition-agent-roles、実行フローはworkflow-design-facilitationへ渡す。結果で選び直す時はdecide-trial-next-stepへ戻し、拡大も縮小も選択肢に残す。

## 成果と完了

[委任記録の比較欄](../../../templates/field-work/delegation-record.md)へ必要な候補と理由を残す。新しい様式を埋めるために作業を増やさない。
誰が何を決めて動かす構成か、今試せる範囲、未決、選択が変わる条件を説明できる。形の名前を実装・権限・価値の証明にしない。
選択肢の原理は[自動化の境界](../workflow-design-facilitation/references/automation-boundaries.md)の必要箇所だけ読む。
