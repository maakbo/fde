# 最近の一件を担当者とたどり、現状の入力・判断・受渡し・例外を記録する

## 開始入力

対象業務、許可された一件の説明/資料、担当者の言葉。
今ある事実から仮説/下書きを返し、不足を優先して確認する。実際の権限・合意・観測を代作しない。

## 実行

1. きっかけと終了/受取者を確認し、実観察・担当者申告・資料記述・架空例を区別する。
2. 誰が何を受け、何を見て何を返したかを順に聞く。5W1Hの不足を、相手が答えられる具体的な問いで補う。
3. 迷い、待ち、差戻し、普段と違う場合、担当不在をたどる。許可のない原画面/動画や個人情報の原本を要求しない。
4. 現状の仮説を短い文/表で返し、その一件と例外を通して訂正を受ける。改善案は別欄へ退避する。再reviewなど望ましい手順でも、記録/回答にない工程をAs-Isへ補作しない。実施有無が不明なら未確認とし、変更案へ分ける。
5. 訂正した箇所、根拠、未確認と確認先を現状記録へ戻す。観測していない時間や毎回の慣行を一件から推定しない。

## 成果と完了

[作業の記録](../../../templates/field-work/case-observation-record.md)の必要な欄を使う。
開始→成果の受取までが根拠付きで追え、通常/例外と改善の着想が混ざっていない。
原理や手法の違いが判断に必要な時だけ[業務分析の判断](../../../guides/field-work/references/work-analysis-methods.md)を読む。
不一致や新条件は該当作業/判断者へ戻す。全様式の記入を開始条件にしない。
