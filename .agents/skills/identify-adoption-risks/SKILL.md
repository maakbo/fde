# AI導入の対象業務から具体的失敗と影響を洗い出す

## 入力

対象業務と実行範囲、入力/出力/操作、関係者の懸念、既知の失敗/観測。
不足は仮説/未確認を示し、今ある情報から返せる下書きを進める。実際の判断・権限・測定値を補作しない。

## 実行

1. 対象の仕事と受取者、起きると困る結果を確認する。AI一般の不安一覧だけを作らない。
2. 正常の一件をたどり、入力/根拠/判断/操作/受渡しで何が誤るか、誰に影響するかを挙げる。既知の観測、担当者申告、想定失敗を分ける。
3. 出力の誤り、使われない/確認負担の増加、目的や管理者/版の不明、情報利用や偏りを点検する。この分類へ合わない失敗も残す。
4. 発生条件、影響範囲、検知までの遅れ、戻せるかを整理し、今の対策と未確認を聞く。確率や重大度の数値を創作しない。
5. 観測がない失敗を起きていないとせず、少数の成功例を安全の証拠にしない。どれを先に調べるかを影響と根拠から提案する。
6. 失敗IDと具体例/影響/根拠/確認先を、対応設計と評価へ渡す。リスク受入や運用開始を勝手に承認しない。

## 成果と完了

[失敗台帳](../../../templates/field-work/risk-and-operation-record.md)。対応はdesign-risk-responseへ。
対象業務の失敗と影響/確実さが追え、優先して検証する理由と未確認がある。
