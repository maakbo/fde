# 相手の仕事に沿ってAIへ任せる仕組みを説明する

## 開始入力

説明したい相手の役割、知りたい点、本人の言葉、現在分かる業務例。
不足していても許可された仮説/下書きは進め、どこから未確認かを明示する。

## 実行

1. 相手が決めたいことを一文で捉える。導入賛成を説得目標に置かない。
2. 入力から結果を返す支援と、目標に沿い参照・操作・結果確認を進める仕組みを、その相手の一件で説明する。
3. 判断する部分、根拠を参照する部分、外へ作用する部分を区別し、人の担当と未実装を示す。
4. 学習/検索/履歴保存、自然な出力/確認済み事実を取り違えていたら短い対比例で直す。原理は必要な分だけ参照する。
5. 「この仕事なら、何を任せて何を自分で確かめると思うか」を返してもらい、違う理解を訂正する。相手の返答がなければ理解確認は未実施とする。
6. 30秒程度の説明、仕事上の例、できること/条件/できないこと、残った問いを返す。汎用知能や製品の宣伝を導入効果の証拠にしない。

## 完了と戻り先

相手の判断に必要な違いと条件を説明でき、相手の実回答または未確認が残る。説明文の作成だけで現場理解や合意を完了としない。
入力そのものが異なる時は対象業務の確認へ、判断材料の欠落は資料/担当者へ、後続の失敗は該当作業へ戻す。

## 成果と必要時の参照

説明の原理→[判断の基礎](../../../guides/field-work/references/decision-foundations.md)。次は候補業務が分かればclassify-task-natureへ。
原理/判断の確認が必要な時は[判断の基礎](../../../guides/field-work/references/decision-foundations.md)の該当項目のみ読む。
