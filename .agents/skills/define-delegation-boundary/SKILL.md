# 人とagentの提案・確定・実行・確認の境界を操作単位で決める

## 開始入力

業務フロー、実施操作、根拠資料と現時点の許可、影響/可逆性、実際の責任者。
不足していても許可された仮説/下書きは進め、どこから未確認かを明示する。

## 実行

1. 最終成果へ至る操作を列挙。起動の方法と、起動後に許される範囲を分ける。
2. 各操作に提案役/確定役/実行役を置き、既に与えられた許可の根拠を記す。架空の役割は演習と明記。
3. 影響範囲、やり直し、検知の遅れ、根拠不足から、実行前の確認/条件付き自動処理/人主導を具体的に提案する。
4. 確認が必要なら誰が何の根拠をいつ見て何を決めるかを指定。既に許可内の下書きや検証へ無条件の再承認を増やさない。
5. 停止する操作、継続できる業務、人への返却、復旧・再開条件を記す。「AI停止」で業務全体を止めない。
6. 通常/情報欠損/許可外の各一件を追い、未許可の更新・送信が漏れていないか確認。人の回答が未取得なら提案として返す。

## 完了と戻り先

各操作の許可/判断/実行/確認時点/例外が追える。設計上の提案と実際の承認は区別され、実装へ未決事項を渡せる。
入力そのものが異なる時は対象業務の確認へ、判断材料の欠落は資料/担当者へ、後続の失敗は該当作業へ戻す。

## 成果と必要時の参照

出力は[委任契約](../../../templates/field-work/delegation-record.md)。実行構成をpartition-agent-rolesへ渡す。
原理/判断の確認が必要な時は[判断の基礎](../../../guides/field-work/references/decision-foundations.md)の該当項目のみ読む。
