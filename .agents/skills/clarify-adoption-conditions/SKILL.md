# 導入条件のすり合わせ

## 始める条件

対象業務と受取者、現行/変更案、関係者の発言と具体例、現在の許可・判断者。不明でも仮の整理を返し、全員への面談や文化診断票を開始条件にしない。

## 手順

1. 実行する人、成果を受け取る人、決める/支える人のうち、今回の変更に関わる役へ話を聞く。役職や部署から考えを推定せず、本人の言葉と聞けていない人を分ける。
2. 最近の仕事で何を失敗と考え、誰が発見/修正し、何を守っているかを具体例でたどる。品質を大切にする姿勢は検証の協力にもなりうる。異議や正確性の要求を文化的な抵抗と断定しない。
3. 過去の導入で役立ったこと、増えた負担、放置された失敗と、今回避けたいことを聞く。意思決定は誰が何を見て行い、専門確認/資源の確保は誰へ頼むかを確かめる。人数や「慎重な組織」といった印象から期間・方式を決めない。
4. 発言→守りたいこと/懸念→支持する事例→試行で確かめる条件→支援/判断者を短く返す。「この条件なら、どの範囲を試せますか」と具体例で訂正してもらう。返事がなければ提案/確認待ちとし、合意にしない。
5. 条件を、設計/検証で直すこと、説明・練習で確かめること、担当/時間/資料アクセスが必要なこと、組織の判断が必要なことへ分ける。説明会だけで技術や体制の不足を解決しない。雇用・評価・責任について権限外の約束をしない。
6. 既に許可された準備と、条件がそろうまで止める操作を分け、次の担当・根拠・未決を返す。懸念が解けたかは実際の発言や行動で再確認し、関係者の状況や負担が変われば見直す。

## 成果と完了

[体制・定着計画](../../../templates/team-adoption-brief.md)の本人の言葉/支援表と「導入条件を具体例で確認する」を使う。守る価値と懸念が試せる条件に結び付き、提案/訂正/合意/未回答、次の確認先が区別される。
操作の提案/実行/停止は[委任範囲の設計](../define-delegation-boundary/SKILL.md)、体験は[実務練習](../rehearse-ai-assisted-work/SKILL.md)へ渡す。文化が改善した/現場が納得したと、作成文書だけで結論にしない。
