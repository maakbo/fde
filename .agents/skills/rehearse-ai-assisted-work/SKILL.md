# AI協働の実務練習

## 始める条件

練習する業務/受取者、合意済みの範囲、許可資料と環境、役割/委任、期待成果、困った時の相談先。実データが使えなければ架空の題材で始め、実本人の能力確認と区別する。

## 手順

1. 参加者が自分の仕事で判断する場面を選ぶ。管理職なら投資・業務方針の材料、開発者なら設計やコードの確認など、必要な成果を具体化する。全案件で経営者の体験を先行条件にせず、テーマに必要な決定者へつなぐ。
2. 今回の入力、参照する資料/版、AIが返す成果、人が確認する箇所、許可/禁止、終了時に渡す相手を本人と置く。専門開発やエージェント構築を全員に要求しない。資料の用意や権限が足りなければ、許可内の部分だけ練習する。
3. 通常の入力で、参加者が依頼し、返った案を根拠/要件に照合し、採用・訂正・返却の理由を述べ、次へ渡すところまで行う。進行役の操作を見ただけで本人が実行できたとしない。代行や手助けをした箇所を残す。
4. 対象に必要な誤り・不足・例外を一つ加え、何を使わず、何を保持し、誰へ戻すかを試す。確認者の時間・資料アクセス・拒否/訂正の権限がなければ、その不足も返す。確認ボタンを押せたことを品質保証としない。
5. 見本を丸写しせず別条件を本人が行い、理由を説明してもらう。通常/例外ごとに実行した役、入力・成果、発言/観測、支援と残る確認を記録する。参加者が不在、代理のAI、架空回答なら、誰の何を検証できたかを明記する。
6. 本人の疑問、確認/修正の負担、役立った条件と使えなかった条件を回収する。デモの速度や練習時間の長さを成否にせず、根拠を説明し、誤りを直し、不明を返して受取者が使えるかを見る。現場効果や人材評価は別の測定/判断へ渡す。
7. 誤りを原資料/入力/Skill/評価ケースへ戻して再試行し、次に自分で行う作業・相談先・再確認の機会を決める。会議など既存業務へ組み込む場合は議題/入力/確認/担当/負担を決め、強制利用や成功談の提出を定着と扱わない。

## 成果と完了

[体制・定着計画](../../../templates/team-adoption-brief.md)の「実務練習の実施」を使う。担当者が何を実行/説明/訂正できたか、進行役が補ったこと、未確認と次の支援が分かる。実本人の練習、AIによる手順の適用、机上の台本を区別し、開始の承認や現場定着へ格上げしない。
背景と問いは[導入の対話と練習](../../../work/operations/references/adoption-dialogue-and-practice.md)。全体進行は[チーム導入](../team-adoption-facilitation/SKILL.md)、効果は[試行評価](../ai-pilot-evaluation/SKILL.md)へ返す。
