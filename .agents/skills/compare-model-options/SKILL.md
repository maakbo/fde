# 作業ごとの方式・モデル候補を同じ条件で比較し、採用範囲と追加試行を決める

## 開始入力

作業と期待結果、利用できる根拠、候補、品質/権限/待ち/費用条件。
不足していても許可された仮説/下書きは進め、どこから未確認かを明示する。

## 実行

1. 依頼の目的と必須条件を確認。未合意は仮条件として記す。固定処理・人の方法を基準候補に残す。
2. 通常/不足/例外の同じ入力と期待結果を用意し、確認役と誤り種類を決める。重みや合格率を捏造しない。
3. 実製品の比較なら公式の仕様・データ条件・価格を確認日付きで確認する。接続不可なら製品採用確定を避け、方式比較や架空条件の算術を先に返す。
4. 許可された範囲で候補を実行し、入力版、モデル/設定、出力、分母、誤り、応答/確認時間、費用を比較。未実行や提供者申告を実測へ格上げしない。
5. 必須条件を先に照合し、違反を総合点で打ち消さない。役割分担の複雑さと引継ぎ負担も比較する。
6. 単一方式、段階的な切替、作業別ルーティングを比較し、採る範囲/不採用理由/戻す条件/次の試行を返す。根拠不足なら限定候補という結論でよい。

## 完了と戻り先

比較条件と観測の確実さが揃い、選定根拠と保留が追える。実行権限がなければ評価計画までとし、測定完了としない。
入力そのものが異なる時は対象業務の確認へ、判断材料の欠落は資料/担当者へ、後続の失敗は該当作業へ戻す。
