# 規定された手順と実際の一件の差を照合し、工夫・例外・統制上の未決を分ける

## 開始入力

手順書と版、一件の説明/観測、影響する成果と責任。
今ある事実から仮説/下書きを返し、不足を優先して確認する。実際の権限・合意・観測を代作しない。

## 実行

1. 同じ対象/版/場面で比較できるか確認し、資料の記述と現場の説明を別に置く。
2. 省略/追加/順序/判断/受渡しの差をID付きで挙げ、誰が何のために変えたかを聞く。
3. 工夫の可能性と、契約/規程/品質統制に触れる可能性を分ける。現場の実態を自動承認せず、マニュアルも絶対視しない。
4. Why不明なら保持しつつ目的/確認内容/管理者を確認する。知らないことだけで削除候補を確定しない。
5. 現状記録へ差を戻し、改善で扱う候補/要確認/残す条件を渡す。規程改定や統制解除を実行したことにしない。

## 成果と完了

[作業の記録](../../../templates/field-work/case-observation-record.md)の必要な欄を使う。
規定/実態/理由の確実さ/影響/確認先が区別され、現状と改善の双方へ引継げる。
原理や手法の違いが判断に必要な時だけ[業務分析の判断](../../../guides/field-work/references/work-analysis-methods.md)を読む。
不一致や新条件は該当作業/判断者へ戻す。全様式の記入を開始条件にしない。
