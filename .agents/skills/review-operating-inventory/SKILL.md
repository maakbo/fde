# 導入した仕組みの目的・管理者・版・利用・負担・失敗を棚卸し、継続/改善/停止の判断材料を返す

## 入力

対象一覧、目的と許可、参照/実行の版、利用/失敗/負担の記録、管理/運用者についての情報。
不足は仮説/未確認を示し、今ある情報から返せる下書きを進める。実際の判断・権限・測定値を補作しない。

## 実行

1. 台帳と実物/観測で何を比較できるか確認する。記録がない対象を管理済みや安全と扱わない。
2. 各対象の目的、現場利用者、実管理者/運用者、参照と実行の版、更新状況、アクセス範囲、停止/再開の方法を照合する。
3. 出力量や利用回数だけでなく、誰がどの仕事に使い、確認/修正/支援の負担と成果に何が起きたかを見る。少ない利用は原因調査へ、無条件の強制や廃止へ飛ばない。
4. 旧版、担当不在、観測欠損、目的外利用、失敗増などを具体的に記し、影響する操作と現場の仕事を切り分ける。
5. 継続/改善/限定停止/調査の提案と根拠、次の担当/確認条件を返す。停止/権限変更/展開は既存許可に沿い、未許可の操作を実施しない。
6. 決定者の実回答、更新した台帳、未確認と次の見直し条件を残す。棚卸し文書だけで現場定着を完了にしない。

## 成果と完了

[運用棚卸](../../../templates/field-work/risk-and-operation-record.md)。具体的な失敗はidentify-adoption-risks、対応の穴はdesign-risk-responseへ戻す。
対象ごとの実態と記録の差、理由付きの提案、担当/未決/次の条件が追える。
