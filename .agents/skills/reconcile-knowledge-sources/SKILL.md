# 知識の候補を承認済みの根拠と適用範囲・有効状態へ照合し、現行/保留/失効を整理する

## 入力

対象業務/判断、許可された事例や資料、知識の候補と所有者について分かること。
不足を明記し、今ある情報から返せる仮説/下書きを進める。録音/全会議収集/個人情報原本の保存を開始条件にしない。

## 手順

1. どの判断へ使う知識かと利用許可を確かめ、候補記録/規程/要件/事例を対象と版で揃える。
2. 各資料の管理者/決定権、有効/草案/失効、適用範囲、更新日、矛盾を記録する。新しい日付だけで置換しない。
3. 条件や例外が一致するかを具体例で照合し、担当者の工夫と正式な要件を別の状態にする。優先順位が未確認なら片方を勝手に正本にしない。
4. 現行利用できる範囲、確認待ち、過去の意味を残す履歴を区別する。未許可/範囲外の情報を参照可能にしない。
5. 訂正の所有者/決定者、変わった時に影響する知識や利用先、次の確認条件を返す。実際の索引/配備/キャッシュ更新は実施有無を別に残す。
6. 矛盾が残る判断は人へ返しつつ、確かな部分の下書きや検証は続ける。知識所有者の回答をagentが作らない。

## 成果と完了

[作業の記録](../../../templates/field-work/conditional-knowledge.md)を必要な範囲で使う。
資料と知識の適用範囲/権限/状態/矛盾が追え、使える部分と保留/更新先を分けられる。
背景の区別が必要な時だけ[知識を使える形にする判断](../../../guides/field-work/references/knowledge-in-work.md)を読む。
