# 相談の仕事・業務・作業の粒度を揃え、今扱う業務と親子の境界を決める

## 開始入力

本人の言葉、仕事の目的、関係者と成果、最近の一件。
今ある事実から仮説/下書きを返し、不足を優先して確認する。実際の権限・合意・観測を代作しない。

## 実行

1. 誰の仕事かを置く。FDEの導入支援、改善対象の開発業務、製品利用者の業務を区別する。
2. 目的/役割、繰返して成果を返す流れ、具体行為、クリック等の手順を元の言葉で並べ、親IDと仮の層を付ける。
3. 業務ごとに供給元/入力/変換/成果/受取者を短く記す。受取者が使える成果か、隣の業務と同じ広さかを点検する。
4. Contextで話す兄弟業務と、Flowで詳しくする一業務を選ぶ。細かい作業は削除せず子へ移す。
5. 業務の説明を返し、通常の一件をどの業務が受け、何を返すかで訂正してもらう。回答がなければ仮説のまま返す。

## 成果と完了

[作業の記録](../../../templates/field-work/work-grain-record.md)の必要な欄を使う。
親の仕事→選んだ業務→子作業が追え、同じ図で混ぜない範囲と未決がある。
原理や手法の違いが判断に必要な時だけ[業務分析の判断](../../../guides/field-work/references/work-analysis-methods.md)を読む。
不一致や新条件は該当作業/判断者へ戻す。全様式の記入を開始条件にしない。
