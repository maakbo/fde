# 経験者の判断を、場面・理由・条件・例外・根拠と更新先がある知識記録へまとめる

## 入力

対象業務/判断、許可された事例や資料、知識の候補と所有者について分かること。
不足を明記し、今ある情報から返せる仮説/下書きを進める。録音/全会議収集/個人情報原本の保存を開始条件にしない。

## 手順

1. 誰がどの仕事の何を判断するために使うかを置き、頻度/影響/困る判断から小さな対象を選ぶ。全組織の知識収集から始めない。
2. 最近の一件と違う一件を聞き、目的/価値、判断条件、手順、操作を分ける。必要時はelicit-tacit-decisionsを使い、経験者が気にした手掛かりと反例を残す。
3. 条件→判断/行為→理由/根拠→不足時の返却という形へ仮説化する。相関、体感、個人の工夫を必須規程や確定した原因にしない。
4. 原資料/事例の版と箇所、適用範囲、例外、所有者と変更権限、確実さ、確認状態、更新条件を付ける。資料がなくても依頼文から言える範囲は仮説として返す。
5. 経験者へ短い記録を返し、具体例と反例で訂正を受ける。実回答/演習回答/未回答を区別し、無回答を確認済みにしない。
6. 次の人が使う入力/判断/確認と、未解決を人へ返す位置を示す。知識記録の完成を実装/現場技能の移転と混同しない。

## 成果と完了

[作業の記録](../../../templates/field-work/conditional-knowledge.md)を必要な範囲で使う。
対象場面と根拠/理由/条件/反例/状態/更新先が追え、経験者の確認と未確認が分かれる。
背景の区別が必要な時だけ[知識を使える形にする判断](../../../guides/field-work/references/knowledge-in-work.md)を読む。
