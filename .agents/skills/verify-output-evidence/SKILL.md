# 生成物の主張や操作を原資料・期待結果・許可へ照合し、修正と再確認へ返す

## 入力

照合する成果、許可された根拠資料/版、期待結果、操作許可、確認者の役割。
不足は仮説/未確認を示し、今ある情報から返せる下書きを進める。実際の判断・権限・測定値を補作しない。

## 実行

1. 成果と使用資料の版、対象/期待結果、確認する範囲を確かめる。作成者と独立した確認なら入力と役割を別にする。
2. 数値、仕様、理由、評価、承認や実行済みの主張を取り出し、事実/解釈/仮説/未確認に分ける。
3. 原資料の該当箇所と適用条件へ照合する。引用先があっても、その版/範囲/根拠自体が適切かを見る。原資料がない時は原文照合を未実施とし、依頼文で確認できる範囲を返す。
4. 必要な条件の抜け、作られた仕様/数値、主観の事実化、権限や承認の飛躍、実施と計画の混同を確認する。資料間矛盾は片方を勝手に正本にしない。
5. 不一致の箇所/根拠/期待/影響/戻し先/具体修正を、受取者が内部経緯なしでも分かる言葉で返す。全体の成果を作り直す前に該当作業へ差分を返す。
6. 修正版を同じ根拠と条件へ再照合し、解消/残存/未確認を記録する。架空の人の承認で閉じず、独立確認の実施範囲を示す。

## 成果と完了

[根拠の照合](../../../templates/field-work/context-and-evidence-record.md)。根拠不足はdesign-task-input、仕様解釈の未決は元の判断者へ戻す。
確認した主張と根拠/判定/影響/修正/再照合が追え、未確認を正解へ格上げしていない。実モデル全体の品質や現場効果を保証しない。
