# 原資料の変更を参照単位・索引・キャッシュへ反映し、旧情報の除外と更新後の確認をつなぐ

成果は[共通の成果形式](../../../work/references/artifact-contract.md)と、この作業が参照する型の必須項目を保つ。既存記録への追記でも同じ項目を引き継ぐ。

## 入力

対象の判断・利用者、許可された原資料/版と一件の記録、既存の属性/参照単位/確認結果。
不足があっても作れる下書きを返し、原文・許可・実測の不足を補作しない。

## 手順

1. 対象業務/質問と利用者、原資料ID/現在の参照版/派生単位・索引・キャッシュ等、更新/切替の許可と担当を確認する。既存の台帳・属性・照合結果を引き継ぎ、不明な権限を補わない。
2. 変更申告・差分/版・更新検知・定期確認から変更候補を絞る。reconcile-knowledge-sourcesで承認状態/対象/発効と失効/利用権限を確認し、新しい日付や草案を即時の現行根拠にしない。モデルの属性推定を承認にしない。
3. 変更/削除/移動/権限変更が影響する単位と参照先を追い、必要箇所だけ候補版へ反映する。原本履歴は保ち、ID/位置/条件/例外を引き継ぐ。原本の履歴や削除だけで派生索引の旧情報も消えたとはしない。
4. 通常/例外/適用外/時点違い/許可外のうち対象に必要な質問で、候補の取得と回答入力・主張を確認する。evaluate-retrieval-evidenceの結果を再利用する。未実施の埋込み・索引・モデル検証を完了にしない。
5. 対象環境で許可された切替時だけ、対象と評価時点に適合する参照集合を有効にし、不適用の旧単位・キャッシュ・権限を除外して切替後も確認する。切替途中や反映失敗の扱い、版の混在を防ぐ方法と担当を決める。設計だけなら切替を実施したと記録しない。
6. 候補の失敗/未承認/根拠欠損なら有効化を保留し、差戻し先と再試行を返す。旧版へ戻す場合も当該対象/時点で有効かを再確認する。失効/権限喪失した旧版を惰性で使わず、必要なら依存する回答だけ保留して人の仕事へ返す。
7. 変更ID/版/確認条件/実結果/実施者/未決/次の更新契機を記録する。自動/定期/現場報告は影響と頻度から選び、入力者の訂正を元資料へ戻す経路を持つ。更新設計、ローカル演習、実サービス反映、現場効果を分ける。

## 成果と完了

[既存の記録](../../../templates/knowledge-use-brief.md)の必要箇所だけ使う。
変更候補→有効条件→派生先の反映/旧情報の除外→同条件/別条件の確認→切替/保留/復旧が追える。実施範囲と未実装、次の担当が分かる。
原理は[読みやすい原本と更新運用](../knowledge-stewardship/references/knowledge-and-retrieval.md#読みやすい原本と更新できる運用)の該当箇所を参照する。
