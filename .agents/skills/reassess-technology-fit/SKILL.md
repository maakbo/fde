# 技術や業務条件の変化を、対象業務の未達・品質・負担・費用へ結び付けて再評価する

## 入力

現行方式と選定理由、未達/観測、変化の情報、守るべき業務条件。
不足は仮説/未確認を示し、今ある情報から返せる下書きを進める。実際の判断・権限・測定値を補作しない。

## 実行

1. 現行が何を満たし何に困っているか、今回変わった情報がどの条件へ関係するか確認する。単なる新製品紹介を採用理由にしない。
2. 入力形式、根拠取得、モデル能力、操作/接続、運用条件等から関係する候補だけを選ぶ。画像入力や小型化/推論能力等のラベルで性能/価格を決めない。
3. 実製品の仕様/価格/利用条件を根拠にする時は公式一次資料の版と確認日を調べる。提供者の申告と自分たちの観測を分ける。
4. 現行維持も含め、同じ業務入力と期待結果で品質/誤り/待ち/確認負担/全費用/保守を比較する計画を作る。未許可のサービスへ実資料を投入しない。
5. 必須条件を変えるなら理由と判断者の実回答を残し、評価を通すために条件を下げない。切替の移行/戻し/知識更新の負担を含める。
6. 今試す/将来条件が変わったら再評価/採らないを理由とともに返す。比較未実施は試行案まで、次に何が分かれば判断が変わるかを残す。

## 成果と完了

[方式の再評価](../../../templates/field-work/technology-reassessment.md)。実比較はcompare-model-options、全費用はestimate-total-costへ。
業務の条件変化から試す理由/試さない理由が追え、比較条件と費用/運用/戻しがある。ニュースや少数例を品質実証としない。
