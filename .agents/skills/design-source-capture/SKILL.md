# 判断に必要な記録を自然に残せる入力項目・参照・確認を設計する

成果は[共通の成果形式](../../../guides/field-work/references/artifact-contract.md)と、この作業が参照する型の必須項目を保つ。既存記録への追記でも同じ項目を引き継ぐ。

## 入力

対象の判断・利用者、許可された原資料/版と一件の記録、既存の属性/参照単位/確認結果。
不足があっても作れる下書きを返し、原文・許可・実測の不足を補作しない。

## 手順

1. 誰のどの判断に使う記録かと、一件の入力/受取を確かめる。頻度・誤りの影響・整備費・入力者の負担から対象を絞り、全過去資料の整備を開始条件にしない。
2. 実物の一件から、主体/対象/行為/判断と理由、根拠ID/位置、条件/例外、不明を分ける。「例の件」等の参照先は許可された根拠へ照合し、不明なら実名や仕様を推測せず確認待ちにする。
3. マスターID/選択肢/型/単位/日付の意味と必要な入力検査を置く。表記揺れは根拠のある対応表で扱い、似た名称だけで同一物へ統合しない。必須は受取判断に必要な範囲へ絞り、原記録と対応を残す。
4. 表の結合・色・複合項目は、見出し/行列/単位/凡例との対応を確かめた参照用の構造へ。画像の意味は許可された実物と位置を確認し説明を添える。原本の体裁を壊さず、未見の画像や凡例なしの色を意味付けしない。
5. 作成/更新の際に誰が何の根拠から入力・確認するかを決める。属性の定義はdesign-source-metadataを再利用し、AIのタグ/参照補完は候補と確定を分ける。入力者に転記だけを増やさず既存ID/記録を流用する。
6. 曖昧な参照、未登録の名称、単位/凡例不足などの一件を通し、受取者が判断できるかと入力負担を確認する。欠損を都合よく補わず、入力項目や参照の案を直して同条件と別条件を試す。
7. 今後の入力ルールと、今回必要な既存部分の訂正案を分けて返す。参照用の整形/分割はprepare-retrieval-units、既存参照への更新はrefresh-reference-releaseへつなぎ、入力フォームを実装済みにしない。

## 成果と完了

[既存の記録](../../../templates/field-work/data-processing-record.md)の必要箇所だけ使う。
入力項目/意味/参照/確認と、元の一件/未知/原本との対応が追える。新規入力と必要な既存整備、提案と実装/実負担の測定を分ける。
原理は[読みやすい原本と更新運用](../knowledge-stewardship/references/knowledge-and-retrieval.md#読みやすい原本と更新できる運用)の該当箇所を参照する。
