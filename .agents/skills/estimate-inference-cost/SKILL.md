# 件数・処理経路・入出力トークンと単価から推論利用費を見積もる

## 開始入力

期間、件数、経路ごとの呼出し/入出力量、単価と単位/通貨。
不足していても許可された仮説/下書きは進め、どこから未確認かを明示する。

## 実行

1. 実測/申告/仮定を分け、件数と呼出し回数を区別する。経路が比較中のどの方式に対応するか記録し、対応不明の概算を方式間の費用差に使わない。欠損を0にしない。
2. 指示、依頼、根拠、履歴、ツール応答を入力に含め、出力を別に積む。文字数固定換算は仮定の幅としてのみ扱う。
3. 実価格を使う時は公式料金の確認日・モデル・課金単位を記録。架空単価は架空と明記し、通貨換算は別の仮定にする。
4. 各経路の費用を 件数×呼出し/件×(入力量×入力単価/課金単位 + 出力量×出力単価/課金単位) で求めて合算する。
5. 再試行は追加呼出しとして前提を定義する。「20%増」は期待呼出し1.2倍で、全件成功までの再試行確率とは同一視しない。分岐率・キャッシュ・ツール課金等は契約に沿って別に計上する。
6. 通常/処理増/失敗増を分け、単位と計算を機械確認。未見積の構築・整備・確認・運用保守を別欄に残す。API費用だけで安い/ROIがあると結論しない。

## 完了と戻り先

式・単位・期間・仮定・欠損と、何を含まないかが追え、計算が再現できる。件数等が未確定なら条件式と確認先までを成果にする。
入力そのものが異なる時は対象業務の確認へ、判断材料の欠落は資料/担当者へ、後続の失敗は該当作業へ戻す。

## 成果と必要時の参照

出力は[推論費用](../../../templates/field-work/inference-cost-record.md)。総費用/便益の評価へ渡す。このSkill単独では投資判断を完了しない。
原理/判断の確認が必要な時は[判断の基礎](../../../guides/field-work/references/decision-foundations.md)の該当項目のみ読む。
