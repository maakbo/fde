# 現行業務を目的から見直し、排除・統合・順序変更・簡素化の選択肢を比較する

## 開始入力

現行工程と成果、各工程の目的/受取者/確認内容、困りごと、依存/統制/制約。
今ある事実から仮説/下書きを返し、不足を優先して確認する。実際の権限・合意・観測を代作しない。

## 実行

1. 工程を残す意味と誰の価値/必要な統制かを確かめる。理由不明は不要の証拠にしない。
2. なくす/まとめる/順を変える/簡単にする問いで候補を出し、残す案と現行維持も比較する。問いの順序を削除の自動承認にしない。
3. 契約/規程/品質/独立確認、情報の依存、責任の移転を点検し、失われる目的を別手段で保てるか示す。
4. 人/既存機能/規則/AIを残る作業へ割り当てる候補を比較。AIの導入を全変更の前提にしない。
5. 効果/追加負担/変更費/データ/影響/戻せるかを根拠付きで整理し、採る/試す/保留を理由と判断者へ返す。架空の得点/同意を作らない。

## 成果と完了

[作業の記録](../../../templates/field-work/process-change-record.md)の必要な欄を使う。
現行からの変更、残す条件、追加負担と未決が追え、統制を無断で削っていない。
原理や手法の違いが判断に必要な時だけ[業務分析の判断](../../../guides/field-work/references/work-analysis-methods.md)を読む。
不一致や新条件は該当作業/判断者へ戻す。全様式の記入を開始条件にしない。
