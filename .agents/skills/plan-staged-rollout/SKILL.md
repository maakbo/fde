# 段階展開の計画

## 入力

目的/対象業務/受取者、試行結果と条件ID/版/実施範囲、使える環境/情報/操作と許可、利用者/運用/支援/決定者、品質/利用/負担/効果の観測と未確認。既存の試行・役割・リスク・費用・知識記録を引き継ぎ、全工程をやり直さない。

## 手順

1. 今回判断する段階と、変えるものを置く。技術の局所試作、実環境/実利用者の限定運用、同じ機能の横展開、別業務/機能/処理能力の拡張を区別する。pilot/rollout/scalingの名称や人数だけで要件・許可が変わらないとは決めない。
2. 証拠が対象/環境/版へ適用できるか照合し、品質合格、利用可能な体制、業務効果、実際の開始許可を分ける。未検証は開始前の条件と確認先へ。欠けた条件に依存する操作は保留し、既存の許可内の継続/準備まで止めない。架空の入力や役割案を現場の合意にしない。別事例の条件/観測を現在の対象へ引き継がず、参考にした設計案は対象IDと確認状態を分ける。
3. 限定運用の対象/機能/利用者/環境/期間または判断時点を目的と危険の大きさから絞る。資料/送信先/ID・操作権限、データの揺れ、性能/費用、実際の確認/受渡し/支援の容量を確認する。実人が一件を受け取り訂正/拒否できるかはrehearse-ai-assisted-work、体制はdesign-adoption-supportを再利用する。
4. 各段階に開始・継続・拡大の条件ID/根拠/確認者/確認状態を置く。重要条件の未達/欠測を他の数値で相殺せず、段階を進めるために元の閾値を下げない。妥当な要件変更は理由/決定者/版と新条件の評価へ戻す。期間満了だけで自動的に次へ進めない。
5. 品質、意味ある利用、受渡し全体の負担/待ち/下流品質、費用と短期/長期の成果を、既存の測定IDで観測する。対象機会/実使用/修正/差戻し/中断、分母/期間/比較相手/頻度/欠測/確認者を定める。利用回数や好意的感想を価値・安全性・習熟の証明にせず、低利用を強制利用や研修へ直結しない。測れた部分の悪化/未達と、まだ測っていない全体を分けて示す。
6. 悪化/権限喪失/担当不在時に止める操作、途中の候補/利用者への影響、手動代替、復旧先と再開条件/判断者を決める。戻す旧版も現在の対象/権限に有効か確認する。計画しただけの監視/停止/通知/復旧は実装済みにしない。具体制御はdesign-risk-response/refresh-reference-releaseへ差分を渡す。
7. 次の段階で変わる入力/利用者/アクセス/技能/支援量/負荷/責務を比較し、同機能でも受取側の条件で再試行する。新しい判断・外部操作・機能ならDiscovery/Definition/Designへ必要部分を戻す。合格した一件や別チームの結果を、追加範囲の実績にしない。
8. 現場の一件の気づき→条件/理由/反例付きの知識候補→所有者による採否/元資料と指示への反映→次の役/別条件での適用と訂正を組む。write-conditional-knowledge、exercise-knowledge-transfer、refresh-reference-releaseを必要な段階で使い、SECIの名称だけで学習済みにしない。出力を見ただけで人の習熟やモデルの重み更新を保証しない。
9. 継続/局所修正/証拠待ち/停止/段階拡大の案と理由を返し、実決定/許可済みの次の操作と区別する。台帳と実観測はreview-operating-inventory、結果判断はdecide-trial-next-stepへ。開始/次段階の条件、残件/担当、次の再判断時点が追えれば計画案として完了。

## 成果と完了

[AI導入の体制・定着計画](../../../templates/team-adoption-brief.md)の段階展開6列と、既存の評価/リスク/役割記録IDを使う。この作業だけなら目的/対象/版/状態/許可、各段階の条件/担当/観測/停止・戻し/未決、今できる操作/次の判断が必須。全体の体制再設計や全員の懸念調査、未測定の効果記入を要求しない。

段階の違い/原理は[検証と運用の学習](../ai-pilot-evaluation/references/operational-learning.md)。関係者との調整はagree-staged-change/clarify-adoption-conditionsへ、実装・評価・現場開始は別の許可された作業として渡す。計画の完成は導入の実行ではない。
