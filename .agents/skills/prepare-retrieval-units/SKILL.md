# 許可された原資料から、条件と例外・原資料の位置を保った参照単位を作り、代表質問で分割を直す

## 入力

対象の判断と質問、許可された原資料/版、既存の参照単位・属性・試行結果があればその記録。
不足があっても使える部分の下書きを返し、権限・原文・実測の不足を埋めない。

## 手順

1. 対象の判断・利用者・代表質問を置き、資料が少なく直接参照で足りるかも比較する。検索方式やベクトルDBの導入を開始条件にしない。
2. 原資料の利用許可/版/有効状態/対象を確かめる。未決ならreconcile-knowledge-sources、属性の定義が必要ならdesign-source-metadataへ渡し、確認済みの結果を再利用する。
3. 必要な原資料から本文・表の見出し/単位・図の意味を取り出し、元の位置と照合する。抽出未実施の図表を読んだことにせず、未知は別に残す。曖昧な指示語は根拠で参照先を確かめ、結合表や色は対応/凡例を照合した派生表にする。原本を上書きせず、今後の記録の改善はdesign-source-captureへ返す。
4. 見出し/話題を候補に、条件と例外、質問と回答、手順の前後を保つ参照単位を作る。離れた条件は出典付きで同じ利用文脈へ結び、単純な文字数分割や要約で義務を落とさない。
5. 原資料ID/版/位置、対象/状態/利用範囲を各単位へ引き継ぎ、元へ戻れるようにする。表題や原資料の属性だけで別版・別対象を混ぜない。元資料を上書きしない。
6. 代表質問と例外で必要な根拠が一緒に参照できるかを試す。広すぎて異条件が混ざる/細かすぎて例外を失う箇所を直し、同じ質問と別条件で再確認する。
7. 検索/直接参照へ単位・根拠・未決を渡す。ベクトル化/索引が必要なら、対象環境での方式/更新/権限/容量を実装担当へ渡し、文書整備だけで稼働済みにしない。

## 成果と完了

[既存の記録](../../../templates/field-work/data-processing-record.md)を必要な箇所だけ使い、同じID/版/未決を引き継ぐ。
参照単位→原資料/位置/条件/例外→質問での確認→修正/未決が追える。方式の候補と実索引/検索の動作を区別する。
原理と選択肢は[知識を探して使う判断](../knowledge-stewardship/references/knowledge-and-retrieval.md#ragを準備と利用に分ける)の該当箇所だけ読む。
