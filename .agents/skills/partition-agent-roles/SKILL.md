# agentの役割と受渡しを分け、単一手順か複数agentかを比較して実行構成を渡す

## 開始入力

一連の作業、委任契約、根拠・状態・利用操作、期待出力と失敗例。
不足していても許可された仮説/下書きは進め、どこから未確認かを明示する。

## 実行

1. 一連の成果を保ちつつ、目的/必要知識/出力/検証が変わる境目に役割を置く。各質問やクリックに分割しない。
2. 各役割の入力、必要な参照と版、出力/受取、使う操作、成功判定、不足/誤りの戻し先を定義する。
3. 判断・情報参照/状態・外部操作を点検し、必要/不要/人担当を理由付きで記す。全役割に長期記憶や外部操作を付けない。
4. 単一実行器での手順分割と、複数agentの分担を比較。独立検証、同時作業、権限分離が必要か、引継ぎ量と費用が増えるかを確認する。
5. 分担するなら統括責任、作業の順序/条件、共通成果の版、二重実行防止、失敗検知/差戻し、確認ゲートを置く。選択済みの入力だけ各役割へ渡す。
6. 成功/根拠の旧版/後続失敗を一件ずつ追い、誤りをどの役割へ戻すか確認。実行器の実装・ツール接続は別作業として契約を渡す。

## 完了と戻り先

役割分担の必要性と受渡しが説明でき、通常/失敗で責任が落ちない。実装していない呼出しを実行済みとしない。
入力そのものが異なる時は対象業務の確認へ、判断材料の欠落は資料/担当者へ、後続の失敗は該当作業へ戻す。

## 成果と必要時の参照

出力は[役割契約](../../../templates/field-work/delegation-record.md)。実装受渡しでは既存の[受渡しSkill](../prepare-implementation-handoff/SKILL.md)も必要時に参照する。
原理/判断の確認が必要な時は[判断の基礎](../../../guides/field-work/references/decision-foundations.md)の該当項目のみ読む。
