# 担当者が無意識に使う判断条件を、実例の違いと反例から引き出す

## 開始入力

対象の判断、通常例/違う結果の例、許可された担当者の説明。
今ある事実から仮説/下書きを返し、不足を優先して確認する。実際の権限・合意・観測を代作しない。

## 実行

1. 最近迷った判断を一つ選び、何を見て結果を変えたか聞く。「経験で分かる」で終えない。
2. 判断が異なる二件を比べ、見た情報/閾値/優先条件/例外/確認相手を仮説として整理する。無い数値や規則を作らない。
3. 「この条件だけ変えたら同じ判断か」という反例を返し、担当者の実回答/演習回答を区別して受ける。
4. 条件→判断→返却/根拠/不足時の行先を仮説にし、例外で破れたら条件を直す。答えを知らない相手へ判断の意図を丸投げしない。
5. 合意できた条件と説明だけの仮説、規程/別の判断者への確認を分けて渡す。例数の少なさを万能ルールへ変えない。

## 成果と完了

[作業の記録](../../../templates/field-work/case-observation-record.md)の必要な欄を使う。
判断の根拠/適用範囲/反例/不足時の返却が追え、未知の条件は未知で残る。
原理や手法の違いが判断に必要な時だけ[業務分析の判断](../../../guides/field-work/references/work-analysis-methods.md)を読む。
不一致や新条件は該当作業/判断者へ戻す。全様式の記入を開始条件にしない。
