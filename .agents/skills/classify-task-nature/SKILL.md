# 一連の業務から具体的作業の性質と検証方法を整理する

## 開始入力

誰の業務か、最近の一件や許可された資料、入口/出口。
不足していても許可された仮説/下書きは進め、どこから未確認かを明示する。

## 実行

1. 仕事全体を作業へ飛ばさず、選んだ一つの業務と成果の受取者を確認する。
2. 入口から結果が使われるまでをたどり、各行を「何を見て、何を行い、何を返すか」にする。不足時は仮説と確認先を添える。原資料本文がなくても、依頼に明示された事実・要約を根拠区分付きで使い、そこから作れる下書きまで返す。原文照合が未実施であることと、下書き全体が作れないことを混同しない。
3. 各行に分類・抽出・検索・計算・生成・判断・操作を複数可で付ける。判断内容や登録/送信を文章生成に埋めない。
4. 原資料から確かめられる値、判断の根拠、期待出力、誤った時の影響を記入する。既存資料の更新と重み学習を混同しない。
5. 固定規則/既存機能/人/AIの候補を出す。分類だから軽量モデル、生成だから高性能と自動割当しない。
6. 通常・情報不足・例外を一件ずつ追い、作業間で落ちる判断を修正。比較が必要な箇所と、規則で処理できる箇所を返す。

## 完了と戻り先

対象業務の始まりから受取までが追え、各作業に入力/出力/性質/確かめ方/方式候補がある。不足は明記され、方式未検証を採用確定にしていない。
入力そのものが異なる時は対象業務の確認へ、判断材料の欠落は資料/担当者へ、後続の失敗は該当作業へ戻す。

## 成果と必要時の参照

出力は[作業と手段の比較](../../../templates/field-work/task-design-record.md)。候補方式をcompare-model-optionsへ渡す。
原理/判断の確認が必要な時は[判断の基礎](../../../guides/field-work/references/decision-foundations.md)の該当項目のみ読む。
