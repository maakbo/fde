# 変数と条件分岐

同じ仕事でも、処理や確認相手が変わる条件があります。FDEは担当者の具体例から、その違いを名前のある値と経路へ落とします。変数の数や分岐の細かさではなく、受取者が必要な成果を得られるかで設計します。

| 判断 | 設計すること | 開発チームでの例 |
| --- | --- | --- |
| 二択 | 条件を満たす場合と満たさない場合、それぞれの処理 | 互換性に影響する変更は詳細レビュー、影響しない変更は通常レビュー |
| 振分け | 分類ごとの担当・手順と、未知/競合時の扱い | API・画面・データ変更からレビュー観点を選ぶ |
| 選別 | 項目ごとの採否、除外理由、残るものがない時の戻り先 | 対象に関係し、参照許可があり、現行版の資料だけをレビュー準備に使う |

`0`や`false`は、値がないこととは違います。例えば「互換性への影響なし」は判断結果であり、判断していない状態へ置き換えません。文字列の`"false"`を真偽値として使えるかも、受取契約で明示します。

条件が重なる場合、記述順に偶然決まる実装にしません。複数のレビューを必要とする仕事か、一人へまとめて返す仕事かを確認します。既定値や汎用経路は必要な条件を満たす範囲で使い、資料がない・権限がない状態を覆い隠すために使いません。

通常の対象外を取り除くことと、処理を失敗して人へ返すことは違います。返す場合は、失敗した箇所、保存済みの成果、未実行の操作、担当者が続ける手順を渡します。担当者へ通知するだけで業務が継続できるとは限りません。
