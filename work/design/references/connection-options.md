# 接続方式の比較に必要な前提

接続を共通の形式にすることと、その操作を許可/実行すべきかは別の判断。
MCPは情報交換のプロトコルで、モデルの使い方やコンテキスト管理を全て規定するものではない。
ホスト・クライアント・サーバーの責任を区別し、既存APIをMCPから呼ぶ構成も候補にできる。
接続先が増えるだけでMCPを採用確定にしない。利用環境の対応、既存実装、操作の境界、提供元と保守、
認証・権限、形式/版、障害時の扱いまで含めて比較する。
ツールの発見/呼出しが可能でも正しい選択や許可を保証しない。外部への副作用は操作の契約で制御する。

2026-10-31確認の一次資料:
- [MCP Architecture](https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture): プロトコルの範囲と構成の確認用。
- [MCP Security Best Practices](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices): 接続候補の信頼/認可の検討時に該当部分を読む。技術的対策は実装環境の仕様で再確認する。

これは特定サービスへの接続・導入や認証取得の許可ではない。製品別の対応や価格は選定時に確認する。
