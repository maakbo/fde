# 業務を聞き、組み替え、図で確かめる時の判断

仕事は目的と役割、業務はその目的を実現して繰り返し成果を返す流れ、作業は中の具体行為。
一つの操作を詳しくしたい時は親の業務へ戻って位置を示す。業務の関係図へクリックを詰めない。
IPOは変換、SIPOCは入口と受取者まで、目標分解は作業と実行計画、Flowは順序と役割の受渡しを見る。
どれも正しさを自動保証しない。問いに必要なものを選び、全様式を埋めることを目的にしない。

現状は観察/説明/規定を分ける。資料記述が現状運用とは限らず、現場の工夫も全て適法/承認済みとは限らない。
理由を知らない作業は調査候補であって不要の証拠ではない。チェックの目的や契約/統制を確認して残すか判断する。
5W1Hは聞き漏れを探す手掛かり。質問票の読み上げや固定時間/固定件数の面談ではない。
最近の一件→例外→判断が違う二件→仮説を返す→具体例による訂正→反映で、暗黙の判断を引き出す。
画面や動画の原本取得を必須にしない。許可された匿名例や口頭の追跡でも、根拠と限界を示して進める。

改善案は現状と別に残す。不要をなくす/まとめる/順序を変える/簡単にする問いは選択肢であり、自動の削除命令ではない。
費用ゼロの排除、承認省略、AIなら高速・正確という前提を置かない。業務成果、依存、統制、負担と戻せるかで比較する。
変更後の一件を担当者目線でたどり、入力不足/例外/復旧/受渡しが成立するかを試す。
現状→変更案→差分が基本だが、試作や対話の訂正で上位の目的や現状へ戻れる。全現状確定まで下書きを禁じない。

現実の制約で理想案を採れない場合は、残る負担/リスク、段階案、測定と次の条件を判断者へ渡す。
相手の返答と権限を記録する。無回答や架空の賛成を合意にしない。許可内の下書きまで毎回止めない。
