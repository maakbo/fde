# 成果と受渡しの共通条件

- 相談や入力から、関係する一作業と該当するテンプレートだけを選ぶ。全フォームを埋めることを最初の依頼にしない。
- 既存成果があれば対象版と該当欄を更新し、他の担当の内容は黙って上書きしない。
- 架空設定、相手の説明、観察、計算、仮説、実行結果を区別する。未測定を0へ変えず、役割案を合意済みとしない。
- 返却は対象版、今回作った成果、根拠、未確認と確認先、次に実行できること。足りない一項目だけで無関係な準備まで止めない。
- 数字の閾値・削減率・反復回数を例から移植しない。目的・リスクと資源から決め、未決定は未決定とする。
- 原理の説明と作業手順を保ち、実装Skillへ渡す契約と検証を曖昧にしない。合意・外部操作は許可された範囲のみ。

- 相談者が今回の条件を明示的に決めた場合は、その発言を根拠として区別して使う。原本が必要な照合と、相談段階で進める下書きを分け、原本未提示だけで一律に全作業を止めない。
- 次に進める単位は操作まで具体化する。「文書設計を進める」「実際の試行を始める」「本番へ配備する」の許可と成立条件をまとめてGoにしない。


## 入力は柔軟に、成果の形は揃える

自由な相談から始めてよいことと、成果の必須項目を省いてよいことは別。
新しい成果は下の共通項目と、作業が参照する成果物の型を使う。
既存Issue/PR/文書を更新する場合も同じ意味の項目を保ち、同じ内容の帳票を別に作らない。
共通項目は一つの継続記録にまとめてもよい。作業ごとに同じ情報を複写せず、ID/版で参照する。

| 共通の必須項目 | 残す内容 |
| --- | --- |
| 成果と対象・版 | 成果の種類/識別できる名前またはID、対象の仕事・範囲、元資料/成果の版。既存IDを引き継ぐ |
| 状態 | 下書き/確認待ち/確定等と、その根拠。成果の確認状態と、実装/実行/観測の状態は別に記す |
| 根拠 | 参照箇所、説明/観察/計算/仮説/実行の区別。実際の合意・許可・測定と提案を混ぜない |
| 本文 | 該当する型の必須項目と条件。比較・図・手順・契約等、受取者が使える成果そのもの |
| 未決 | 不明な項目、影響、確認先。未決がない場合もその旨を示す。確認先が不明なら未特定と次の特定方法 |
| 次の受渡し | 次の受取者または未特定、今できる操作、止める操作/条件、次に渡す成果や判断 |

新規のMarkdown成果は「成果名 → 対象/版・状態・根拠 → 作業別の本文 → 未決と次の受渡し」を基本順とする。
既存の項目名/並びに同じ意味がある場合は再整形せず再利用し、リンク先を含め対応が分かるようにする。
図の本文やチャットの短い案内へ管理欄を繰返さず、読者用の図/説明と作業記録をつなぐ。
個人/機密の原資料を標準欄のために収集・転記しない。根拠は許可された識別子や参照範囲に留める。

## 作業別の型で揃えるもの

- **必須**: その成果で次の担当が判断/実行するのに必要な項目。未知でも欄を消さず「未確認」と影響/確認先を残す。
- **条件付き**: 分岐、外部操作、時刻制約など、その条件がある時の項目。条件があれば記載し、該当しないものは理由を添え省略できる。
- **任意**: 説明を助ける例、比較候補の追加、補助図。量を完成条件にしない。

新規成果は、選んだ型の見出しと表の列名/列順/意味/単位を維持し、必須の列を統合・削除しない。案件固有の追加説明は補足へ置く。本文の行数、図の有無、任意節は調整できる。既存業務様式へ統合する場合は同じ意味の欄との対応を明示する。
「必要な欄だけ」は無関係な型を全部使わないという意味で、選んだ成果の必須欄を捨てる意味にしない。
型で区分が未明示の場合は、現時点の成果と受取者に必要な項目を明示して使い、型の管理者へ区分の改善を返す。
全形式の必須/条件付き/任意の棚卸し済みとはみなさない。

## 返す前に確かめる

共通項目と作業別の必須項目が埋まるか、未確認として追えることを確認する。
型だけ揃っても、値・根拠・単位・状態・条件の意味が違えば差し戻す。
次の担当が説明を補作せず使えるかを、一つの通常例と不足/別条件で確かめる。
相談者へ全フォームを先に要求したり、見た目を完成させるために未知を埋めたりしない。
