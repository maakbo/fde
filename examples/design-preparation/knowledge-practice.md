# 「いつもそうしている」を、次の設計でも使える知識にする

設計の引継ぎで困るのは、手順がないことだけではありません。「何を見て判断したのか」が抜けると、次の担当者は例外に出会うたびに聞き直します。
ここでは予約一覧の状態条件を追加する設計を題材に、経験者の判断を記録し、根拠を照合して別の依頼で使うところを試しました。
[入力資料](knowledge-intake.md)はすべて架空です。実在の設計規程、関係者の回答、現場の効果を示すものではありません。

## 新しいメモと、承認された手順が食い違った

手元には、失効したP1、承認済みの現行P2、その後に書かれた未承認メモH3がありました。
P2は「状態条件を追加・変更するときは承認済み状態マスターの版を記載。不明なら推測せずSEへ返す」。H3は「仮の値で進める案」です。
日付で選べばH3ですが、発効も承認もしていません。今回使える根拠は、対象の設計に適用するP2でした。
ナレッジ担当は記録を直せても、P2を変更承認する権限までは持っていません。

経験者の「旧様式にはいつも版がない」という説明も、そのまま規則にはできませんでした。
同じ旧様式で版V5への参照がある事例があるからです。「様式にかかわらず、版への参照を確認する」と整理し、経験者本人の確認は未回答として残します。

## 次の担当者へ渡す記録

演習の知識IDはK-P2。原手順P2を根拠とする知識下書きとして扱い、実運用の承認済み知識とは区別しました。

| 残すこと | この一件での内容 |
| --- | --- |
| 使う場面 | 予約一覧の状態条件を追加・変更する設計 |
| 目的・理由 | 承認済みの根拠を追え、未確認の状態値を設計へ混ぜない。理由は今回の整理で、原資料の引用ではない |
| 条件と手順 | 状態条件を変えるなら承認済みマスターの版を確認・記載。版不明なら未決として担当SEへ返す |
| 具体操作 | 設計票に版・根拠参照・不足事項を記す。チケット更新や送信は今回実行しない |
| 境界 | 表示形式だけの変更とCSV出力には、この手順を適用しない |
| 状態と更新先 | P2を根拠とする演習記録。経験者確認は未実施。記録管理はナレッジ担当、手順変更承認は設計責任者 |

文書を揃えるだけでは、次の人が使えるか分かりません。そこで、完成した解答は渡さず、Skillと生の架空資料から別の実行役に判断してもらいました。

## 下書きを直し、同じ依頼で確かめ直した

別エージェントは先行下書きの三つの誤りを根拠へ照合しました。H3の採用は保留、旧様式の一律差戻しは取り消し、CSVへの手順適用は取り消しました。
訂正後に同じ入力へ適用すると、次の結果になりました。

| 届いた依頼 | 返せたこと | 未確認のまま残すこと |
| --- | --- | --- |
| 状態条件追加、承認済みV5への参照あり | 根拠版V5を設計下書きへ記す | マスター本文がないので状態値は確定しない |
| 状態条件追加、版未記載 | 版不明を未決としてSEへ返す案を作る | 実際のSE回答・送信・設計承認 |
| CSV出力追加 | P2の対象外とし、文字コード・権限・項目範囲の未決を分ける | 別の原資料と決定権者。P2からCSV仕様を作らない |

ここまでは、知識を作った実行役自身による再適用です。別の担当者へ知識が伝わった証明とは分けます。

## 別の受取役には、新しい三件を渡した

次は別の受取役へ知識下書きだけを渡しました。前の三件の完成解答は読ませず、次の新しい入力を使いました。根拠原本の再照合とは別の、記録された知識を使えるかの試行です。

| 新しい入力 | 受取役が返した結果 |
| --- | --- |
| C4：新様式で状態条件を変更、版未記載 | 新様式でも版が分かるわけではない。値を推測せず未決としてSEへ返す案 |
| C5：日付表示だけ変更、別の記述規約は本文未提供 | P2は適用外。別規約の適合や設計承認は判断せず、根拠と確認先を確かめる |
| C6：状態条件を変更、承認済みV6への参照あり、本文なし | V6を根拠版として記す下書きまで。V5に固定せず、状態値は未照合として残す |

作成側が実行前に置いた照合条件と三件とも一致しました。実行したのはAIエージェント間の架空演習で、人の習熟や実モデルの総合的な品質を測ったものではありません。
さらに最初の実行役が自分で設定した別業務の[入力](knowledge-intake.md)でも試しました。研修教材の紙チェックは何を証明するのか不明で、手順書・最近の一件・決定権者・配布許可は与えていません。実行役は元の設計ルールを転用せず、内容/版/配布先/承認を確かめる欄かもしれないという仮説と、管理者・手順の所在を確かめる案まで返しました。欄の廃止や配布の承認は判断していません。この別業務の適用は別役による未知条件の評価とは分けます。

## 手順へ戻した改善と、残る仕事

独立レビューでは、別役へ入力を渡す指示の共有許可が曖昧だと分かりました。
Skillと記録の型へ「共有先・範囲の許可を確認し、未許可なら許可された架空事例か実施案まで」を追加しました。実関係者への送信はしていません。
実際に使う前には、経験者による訂正、正本の所在と利用権限、知識を使う担当者の練習を確かめます。検索索引・配備・キャッシュ更新、追加学習、本番利用、現場効果は未実施です。

使った作業は、[条件付きの知識を作る](../../.agents/skills/write-conditional-knowledge/SKILL.md)、[根拠を照合する](../../.agents/skills/reconcile-knowledge-sources/SKILL.md)、[別の一件で使って直す](../../.agents/skills/exercise-knowledge-transfer/SKILL.md)。
[知識記録](../../templates/field-work/conditional-knowledge.md)と[適用試行](../../templates/field-work/knowledge-transfer.md)の型で、次の担当者へ根拠と未決を一緒に渡せます。
