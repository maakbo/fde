# 検索機能の設計レビュー相談

架空の受注管理システムで、開発チームは「取消済みの受注も、必要な時だけ検索できるようにする」機能を追加しています。基本設計の下書きをAIへ任せ、エンジニアがレビューします。以下の資料・役割・回答はすべて架空で、顧客や会社の実データではありません。

FDEへの依頼は、「下書きが今回の要件に合っていない。どの情報や渡し方を直し、何を確かめればよいか整理して、次の設計レビューへ使える入力とレビュー案を作ってほしい」です。

## 今回の作業条件 / TASK-SEARCH-r3

- 作業：検索機能の基本設計レビュー案を作る。設計の実装や顧客承認は行わない。
- 受取者：開発チームの設計担当とレビュー担当。担当者名・実際の承認者は未定。
- 期待：表示条件、APIとの対応、確認ケース、使用した根拠、未決を短く返す。
- 許可：ここにある架空資料の読取りとMarkdownの下書き。外部送信、コード/DB変更、承認は許可されていない。
- 判定する条件：初期表示、利用者が明示した時の表示、API既定値、設計案と承認済みの区別。

## 参照資料の一覧と抜粋

### RQ-SEARCH-v1 / 旧要件

旧要件では、取消済み受注を検索結果へ含めません。現在の要件としては使用しません。

### RQ-SEARCH-v2 / 現在の要件

今回の機能追加の要件として、架空の業務責任者が選定した版です。ファイルの更新日時で選んだのではありません。

- R1：初期表示では取消済み受注を含めない。
- R2：「取消済みを含める」を明示的に選んだ場合だけ、取消済み受注も検索結果へ含める。
- R3：表示範囲に関係なく、既存の閲覧権限の制約を守る。権限を拡大する変更ではない。
- R4：画面の選択状態をAPIの`include_cancelled`へ渡す。

### API-SEARCH-v1 / 今回も使うAPI契約

- `include_cancelled`は省略可能な真偽値で、未指定はfalse。
- trueなら権限のある取消済み受注も候補へ含める。falseなら取消済みを除外する。
- 文字列`"true"`の受理、画面の実装方式、実際のAPIの動作は、この資料では確認していない。

### CHANGE-MEMO-r3 / 変更メモ

設計担当は、今回の変更ではRQ-SEARCH-v2を使うことを確認しています。API-SEARCH-v1は継続利用します。この記録自体は設計の承認ではありません。

### BILLING-v8 / 請求処理の資料

請求処理に関する別業務の資料です。検索機能の表示条件は定義していません。
