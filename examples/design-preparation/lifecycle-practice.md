# 設計メモを記録し、参照する仕様の版をそろえる

設計メモに「例の件はOK。スクショの通り」と残っていました。これを読んだ次の担当者やAIは、何へのコメントで、どこまで決まったのか判断できるでしょうか。
受注一覧の基本設計を題材に、今後の記録の入力と、改訂した仕様を参照する条件を試しました。[入力](lifecycle-intake.md)はすべて架空で、原本の編集、実サービスの更新、実LLMの評価は行っていません。

## 「OK」の対象を、根拠に戻って限定する

原文N-1には参照ID M-5があり、用意した架空の確認回答では「受注一覧のレイアウト下書きへのコメント」と分かりました。機能仕様やリリースの承認ではありません。
原文は保ち、M-5との対応を残します。次からは対象画面ID、何へのコメントか、参照ID、コメント本文を同じ記録へ入れる案にしました。既存本文を別の台帳へ二重転記させる案にはしません。

マスターM2では「受注一覧」「注文リスト」はO-LISTですが、「注文照会」はO-LOOKUPという別画面でした。似た言い方だからと一つにまとめず、正しい候補を選べる入力へします。
画像I-9は未提供なので、「スクショ」の内容や細部は補いません。

## 見た目を壊す前に、意味を確かめる

結合見出し「受注一覧v2」を持つ原表は、そのまま残します。参照用の派生表では共通見出しを各行へ対応付けました。

| 項目 | 原値と単位 | 今分かること |
| --- | --- | --- |
| 設計工数 | 2人日 | 1人日を何時間とするかは未確認 |
| レビュー工数 | 4時間 | 換算根拠なしに設計工数へ足さない |
| 承認欄 | 青背景 | 凡例がないため承認済みとはしない |

AI候補の「人日は8時間」「青だから承認済み」も、そのまま確定しません。画像の注記や属性は候補と確認結果を分け、次に誰が何を確かめるかを残しました。
ここで試したのは入力項目と派生表の案です。フォーム実装や入力負担の測定はしていません。整備対象も、この設計で使う記録と今後の入力に絞りました。

## 最新の日付ではなく、対象と時点で選ぶ

参照仕様D-Sには四つの版がありました。評価時点を2026-11-01に固定した演習です。

| 版 | 与えた条件 | この時点での扱い |
| --- | --- | --- |
| v1 | 承認済み、11月1日より前まで有効 | 履歴として保持。現在回答の根拠にはしない |
| v2 | 承認済み、11月1日から有効 | 現在の根拠候補 |
| v3 | 新しい更新日だが草案 | 現行にしない |
| v4 | 承認済み、12月1日から有効 | 発効前なので今は使わない |

v2には「状態マスターを参照し、版が不明なら未決としてSEへ返す」とあります。候補単位ができただけでは、索引とキャッシュがv2を返すとは限りません。

## 混在、権限撤回、履歴質問を分けて試す

別エージェントは[標準Pythonの演習コード](lifecycle-lab/check_release.py)と[架空fixture](lifecycle-lab/fixture.json)で、版・発効・権限と、渡された模擬索引/キャッシュ版の整合を確認しました。

```sh
python3 examples/design-preparation/lifecycle-lab/check_release.py
```

| 条件 | ローカルで確認した判定 |
| --- | --- |
| F1：索引候補v2、キャッシュv1 | HOLD。混在したまま進めず、失効したv1へ戻して答えない |
| F2：両方v2、通常/版不明の条件が本文に残る | LOCAL_SWITCH_OK。演習条件に対する切替可否の判定が通る |
| F3：v2の利用権限を撤回 | HOLD。旧版・草案・発効前の版へ迂回しない |
| F4：権限のある履歴確認で10月30日を指定 | その時点のv1を参照。現在の答えとは分ける |

LOCAL_SWITCH_OKは判定ラベルです。コードは索引やキャッシュの内容を更新せず、有効な参照ポインタも実際には切り替えていません。通常/版不明の確認も、短文に必要な文字列が残るかの検査だけで、検索や回答品質の測定ではありません。

## 記録と変更を、次の担当へ渡す

同じN-1と、別名「注文照会」で再照合し、コメントを承認へ広げず、別画面を統合しないことを確認しました。更新側では、原資料・派生先・評価時点・権限・保留理由を同じ記録へつなげます。
実装する時は、変更の検知、候補反映、旧情報の除外、実際の取得と回答、切替後の確認が必要です。失敗時も、失効した根拠へ戻すのでなく、依存する回答を保留して人が適切な原資料へ戻れるようにします。

使ったのは[入力の仕組みを設計する](../../.agents/skills/design-source-capture/SKILL.md)作業と[参照先の更新をつなぐ](../../.agents/skills/refresh-reference-release/SKILL.md)作業です。
既存の[情報と処理の記録](../../templates/field-work/data-processing-record.md)、[知識を使う記録](../../templates/knowledge-use-brief.md)へ必要な欄だけを足し、別台帳を増やしません。
原本の抽出、実索引/キャッシュ更新、重複イベントの処理、実環境の権限強制、実モデル品質、現場効果は未実装・未測定です。
