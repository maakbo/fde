## C：待ちが短く、固定転記が長い場合

- 現状/根拠: CASE-Cには別チームの同程度の機能追加4件でレビュー待ちが各10分以下という架空記録がある。固定転記90分/件の記録もあるが、転記の発生件数は未確認。仮に4件すべてで同じ90分が生じた場合の工数は `4件 × 90分/件 = 360分`。レビュー待ちの合計は最大40分以下だが、案件の並行/直列や時間線が不明なので、360分と比べて全体の経過削減を算出しない。通常ツールでの出力可否は未確認。
- ECRS: 二次表の利用先と統制が不明なので作成工程をなくすとは決めない。同じ確定項目の二重入力をまとめ、一次表を正本として自動出力できるか調べる。変換順序と固定ルールを確認し、手入力を簡素化する通常手段を先に比較する。未確定仕様の判断は人へ残す。
- ボトルネック仮説: CASE-Cには固定転記90分/件の記録があり、レビュー待ちの記録は4件とも各10分以下。転記の発生件数は未確認。人手と待ちを直接比較して全体の経過制約は決められず、並行性/下流も未確認。転記負担の改善余地を先に調べる。管理者役の「作成時間が最大だからC1」は、C1の全文AI下書きと固定転記を混ぜている。固定項目の変換はまず Rule / System の範囲。

## D：C3の文章対応と確認者不在

- 現状/根拠: 条件 D は C3 の文章対応について「AI適合性は高く、人が最後に見るから誤りは許容」との架空発言。一方、確認者は今週0分、代替未定、仕様正本へのアクセス未確認。未検出の要件欠落が設計・実装・テストから落ちる可能性がある。共通品質条件と許可は変わらない。CASE-v1 の待ち値や C の転記値を D の効果根拠には用いない。
- AI適合性: 文脈のある文章対応候補を挙げる作業にはAIを試す理由がある。しかし実用の適合性は **TBD**。確認者に今週使える時間が0分という既知の条件では、正本を見て採否を決める人の確認が成立しない。最終確認を形式的に置くだけで誤りは許容できない。未検出欠落のリスクは **High**。WORK-v1 の遅れ・負担・品質への効果の大きさは **TBD**。今週の実現可能性は確認時間0分という既知の障壁から **Low**、代替体制を整えた後の実現可能性は正本アクセス・許可等が未確認のため **TBD**。今週のC3の実行/受渡しは選ばない。これらの高低は根拠の確かさを表す点数ではない。
- 手段の分離: 固定した資料ID/版の照合は通常の Rule / System を比較できる。文脈対応はAIが候補を提示しても根拠箇所・不一致・未決を示し、正本照合と採否は権限ある人が行う必要がある。仕様決定や欠落なしの保証をAIへ移さない。
- 次の一手: まず責任者役に、確認者または代替の技能・実時間・拒否権、正本と版へのアクセス、欠落を検出する評価例、許可された入力/環境を特定してもらうための確認事項を渡す。確認が成立するまで C3 のAI出力を設計範囲や開発/テストの根拠に採用しない。今週できるのは資料/条件整理の下書きまで。確認体制と正本が揃えば C3 の限定した候補提示を再比較し、揃わなければ人/既存ルールによる根拠照合の範囲を検討する。
- 受渡しの条件と未決: **既知**は「確認者の今週の時間は0分」「代替は未定」「仕様正本へのアクセスは未確認」。確認者の実任命・技能・拒否/訂正権、代替を置ける時期と時間、正本管理者、AI利用環境と許可、欠落の評価方法、停止・回復の責任者は未確認。次の担当は既知の0分を空欄や推定値で上書きせず、代替または後日の時間と正本アクセスを確認する。確認が成立しないまま「人が見る」を実行条件にしない。実任命や開始許可は今回の案に含まれない。
