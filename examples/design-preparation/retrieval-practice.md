# 設計の根拠は見つかったのに、なぜ条件を落とすのか

予約一覧に状態条件を追加する設計で、「候補を絞り込むなら、何を確認すればよい？」と尋ねます。
設計担当に必要なのは、似た文書ではなく、今回の製品版に使える手順と、その例外です。
[架空の入力](retrieval-intake.md)を使い、参照単位を整える作業と、取得した根拠から回答までを確かめる作業を別エージェントで試しました。実会社の資料・LLMサービス・ベクトル検索は使っていません。

## 小さな資料なら、直接読む案も残す

同じ話題の資料には、旧製品版P0、現行P2、新しい日付の草案P3がありました。今回は予約管理v2の設計なので、使う根拠は承認済みP2です。別チーム専用P4は本文の許可もなく、検索候補に出しません。

P2には三つの節があります。状態条件を追加するなら状態マスターの版を記す（§1）、版不明なら推測せずSEへ返す（§2）、CSV出力には適用しない（§3）。
節ごとに切り離すと、§1だけが見つかり、版が分からない時の対応を落としました。この短い資料では三節を出典位置付きで結ぶ案にし、直接全文を読む案も残しました。大きな検索基盤を作ることを開始条件にはしていません。

## 検索と回答の間にも、落ちる場所がある

入力に用意した五つのログを、原文と照合しました。これらは実サービスから採ったログではなく、原因を切り分けるための架空条件です。

| 条件 | 何が分かったか | 戻すところ |
| --- | --- | --- |
| L1：旧版/草案を取得し、草案で回答 | 今回使えない根拠を選んでいる | 対象・有効状態の選別と検索条件 |
| L2：P2§1しか取得できない | 通常の規則だけで、例外がない | 分割と参照単位のつながり |
| L3：三節を取得したが、回答入力は§1だけ | 検索の後で必要な根拠が落ちている | 入力への選択・受渡し・切詰め |
| L4：三節とも入力にあるのに「仮の値で進める」 | 入力にある条件と回答が食い違う | 生成/解釈と根拠照合 |
| L5：回答だけあり、取得と入力が不明 | 回答は原手順と違うが、原因段階は不明 | 取得ID/版/位置と実入力の記録 |

L3を検索方式の変更だけで直そうとしたり、L5をモデル性能の問題と断定したりしないことが、改善の近道でした。
なお、状態マスターの版と本文は元から未提供です。これは検索漏れとは別で、未決としてSEへ返す案までにします。

## 文字検索で、同じ質問と別の質問を試した

[演習用コード](retrieval-lab/search_demo.py)は、標準Pythonの文字列一致だけで候補を探します。[架空資料](retrieval-lab/fixture.json)の内容と対象・状態・利用許可を使い、元の語と、手動で指定した「状態条件」を比較しました。質問理解や埋込みの自動処理ではありません。

```sh
python3 examples/design-preparation/retrieval-lab/search_demo.py
```

元の語と未調整の比較設定ではP0/P3が候補になりました。対象と状態を絞り、語を変えても、節単位ではP2§1だけでした。
三節を結ぶと、§2の版不明時の留保も参照できる候補になりました。別のCSV質問でも、§3の適用外条件を§1–§2と一緒に確かめられました。
未許可を表す検査用の完全架空P9も加え、資料IDに依存せず利用許可の属性で候補から外れることを確認しました。実環境の認証/アクセス制御の検証ではありません。
実行したのは、この小さな文字検索です。回答入力の実装器や実LLMは動かしていないため、本番の誤答が解消した証明ではありません。

## 同じ根拠を、何度も作り直さない

正本を照合したP2のID・対象・状態と、元の§位置を引き継ぎ、別の台帳や同じ主張の確認を増やさずに進めました。
[参照単位を整える](../../.agents/skills/prepare-retrieval-units/SKILL.md)作業と[検索・入力・回答を分けて確かめる](../../.agents/skills/evaluate-retrieval-evidence/SKILL.md)作業で、既存の資料属性と照合結果を再利用します。
原理は[既存の参照知識](../../.agents/skills/knowledge-stewardship/references/knowledge-and-retrieval.md#ragを準備と利用に分ける)、記録は[知識を使う記録](../../templates/knowledge-use-brief.md)へつなぎます。

次は、実装環境で取得から回答入力への受渡しを記録し、必要な例外が残るかを確認します。原資料の更新・索引・アクセス制御の実装と、モデル品質・現場効果は未検証です。
