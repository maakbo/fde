# 設計書をAIへ渡してよいか、判断できる材料をそろえる

要件から基本設計の下書きを作る仕事にAIを使いたい。「社内検索を使うから、設計書を入れても大丈夫だろうか」。
この相談を、技術名ではなく、渡る情報と任せる操作から整理しました。[入力資料](governance-intake.md)はすべて架空です。実在の設計書・契約・個人情報は扱わず、外部サービスへの送信や実担当者への相談はしていません。

## 「社内検索」の先をたどる

案の経路は、社内設計書の断片→社内検索の抜粋→外部モデルサービスS→設計下書き→社内チケット案でした。
検索が社内でも、抜粋は外部へ渡る案です。Sは架空サービスで、保存・学習利用・再委託・地域・削除条件は未確認。「RAGだから外に出ない」とは説明できません。

既存の委任記録W-1、接続記録C-1、失敗記録F-1を引き継ぎました。運用上の提案・内容確定・照合・実装の担当は分かりますが、それだけで法的責任を決めたことにはしません。

## 相手が決められる問いにする

| 判断を担う役割 | 渡したい事実と問い |
| --- | --- |
| 法務 | 原資料の権利・第三者由来、利用目的と地域、Sの契約が未確認。入力/生成/内部利用/外部公開のどの条件を確認すればよいか |
| セキュリティ | 抜粋がSへ渡る案だが、保存先・接続先・権限・停止の実証がない。どの条件を確認し、どう強制して試すか |
| 業務責任者 | 下書き支援に限定するか。誰が原資料へ照合し、何を実装担当へ渡すか。使わない時も人の設計を続けられるか |

入力で与えた架空の役割回答はいずれも判断未了でした。「便利そう」「レビュー担当が見る」から、外部送信や本番化の許可を作りません。
氏名の置換だけで入力許可を証明したことにせず、学習利用と保管、生成物の権利と外部公開の可否も別に確認します。これらは判断のための論点で、この一件の法的結論ではありません。

## 方針を、止められる操作と記録へつなぐ

架空方針A1は、未承認の外部サービスへ機密の仕様やコードを送らない一方、架空資料D-FAKEを使うローカル下書きを許可しています。

| つなぐもの | この一件の案 |
| --- | --- |
| 方針と根拠 | A1、接続C-1、失敗F-1から、未許可のS送信を止める |
| 実行制御 | 送信先・資料範囲・目的・操作の許可を照合。未確認なら送らない。コネクタを止める仕組みは未実装 |
| 必要な証跡 | 対象ID/版・判定・時点・実行主体等を候補にする。閲覧者、期間、削除は確認待ち。原文や全出力の無期限保存を既定にしない |
| 試し方 | 許可範囲の通常例、許可外資料の拒否、判定記録を取得できない例を確認する。今回行ったのは紙上の追跡で、制御の動作試験ではない |

別エージェントの試行では、先行案の七つの飛躍を訂正し、相談材料とこの対応案まで返せました。実データのS投入・実チケット更新・外部公開・本番化を保留しつつ、許可内の架空下書きは続ける形です。
方針を書いたこと、制御を実装したこと、動作を確かめたことを分けて記録しました。

## 台帳の外と、ローカル案も同じように確かめる

提供された部門一覧には、台帳I-1にないBの名称と「管理者不明」という申告がありました。Bの違反や安全を決めつけず、その一覧の範囲で管理者・目的・情報経路を確かめる案にしました。全端末や通信を調べる許可はありません。

別案の「ローカルモデルLならすぐ使える」にも、プラグイン・診断ログ・バックアップ先の確認が残りました。Sとは別の経路として整理し、ローカルという名前だけで外部通信なしとしません。Lを実行したり、実仕様書を投入したりはしていません。

## 条件の確認が進んだら、次の作業を更新する

追加の別条件A2では、架空の三役が「D-FAKEの指定3節だけをSへ渡す下書き試行」の条件確認を終えた、と設定しました。
再試行では、この範囲の相談を最初からやり直さず、次に必要な送信前の制御・接続・停止の実装と試験へ渡せました。条件確認が済んだだけで、未実装の制御を動作済みにせず、試行開始の権限も別に確認待ちへ残しています。今回の実接続・送信禁止は変えていません。

使ったのは[相談材料を作る](../../.agents/skills/prepare-governance-review/SKILL.md)作業と、既存の[委任の境界](../../.agents/skills/define-delegation-boundary/SKILL.md)、[失敗への対応](../../.agents/skills/design-risk-response/SKILL.md)、[運用の棚卸し](../../.agents/skills/review-operating-inventory/SKILL.md)です。
既存の記録IDを使い、方針・接続・責任の台帳を作り直さず、[失敗と対応の記録](../../templates/field-work/risk-and-operation-record.md)へ必要な相談と制御の欄だけを足します。

ここで確認したのは、架空の条件から相談・制御・次の判断を整理する手順です。実法務評価、契約締結、制御の実装/動作試験、実モデルの品質、現場の効果は未実施・未測定です。
