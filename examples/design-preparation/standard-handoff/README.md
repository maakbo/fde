# 設計のAI支援を選び、次の担当へ渡す

設計下書きで根拠を探し直す手間と、レビュー指摘の確認往復を減らしたい。
架空の開発チームで二つの候補を比べ、設計下書きを一件探索する相談から、担当者へ渡せる記録を作りました。
通常の検索機能追加を進めるチームへのAI支援で、製品へAI機能を足す話ではありません。

[相談条件](intake.md)／[設計業務の全体](../README.md)／[成果の型を選ぶ](../../../guides/field-work/references/artifact-types.md)

## 何を次へ渡したか

| 成果 | 次の担当が判断できること |
| --- | --- |
| [候補の比較](artifacts/discovery-brief.md) | C1は相談者が探索対象に指定した候補。量や効果が優れていると証明したわけではない |
| [業務の境界](artifacts/work-grain-record.md) | 誰から何を受け、何を誰へ渡す仕事か。仕事/業務/作業の親子と対象外 |
| [現行の一件](artifacts/case-observation-record.md) | 担当、情報、道具、判断と未確認。実観察と架空説明の区別 |
| [チームの責任分担案](artifacts/team-adoption-brief.md) | 実行/組織判断/相談/共有、時間と不在時の未決。実際の同意は得ていない |
| [試行結果から次を考える](artifacts/ai-trial-brief.md) | 必須条件と人工の観測、修正案・次の検証。平均値だけでは通せない条件 |
| [次へ渡せる範囲](artifacts/delivery-review.md) | 準備を続ける操作、修正/証拠待ち、本番へ進めない理由 |

要件版はv2、成果と条件は同じIDで引き継ぎます。時間や頻度が分からない所は補わず、
C2の週5件を勝手に月換算しません。レビュー担当の時間や開始判断者も、確認済みとして割り当てていません。

## 平均で通してよいか

演習条件では、根拠ID/未決の保持が適合し、参照権限を広げない必須条件に不適合1件という人工観測を与えました。
18/20成功という案があっても、必須条件の未達は相殺しません。修正先と次の検証を返し、
許可された架空の下書き準備を続けることと、実環境試行・本番開始を分けました。
不適合がないと仮定した別条件でも、未確認のレビュー体制を成立したことにはしていません。

この6成果は、別contextのエージェントが相談条件と公開Skill/型を使って実際に作成したものです。
実観察、モデルの実行試験、人の承認、現場の改善効果はありません。表の列と共通項目が揃うことに加え、
未知や未達を保ったまま次へ渡せるかを確認した演習です。
