# レビュー依頼の受付条件：業務要件定義案

- 対象・版・状態：WORK-v1 の設計業務内にある、レビュー依頼の受付。DEF-IN-v1 に基づく Definition 案 DEF-v1。架空資料への実AIによる文書適用であり、現場確認・合意・実ツール/実モデル評価・効果検証・開始許可は未実施。
- 目的：確定要件から基本設計をまとめ、レビューと修正を経て開発へ渡す仕事で、レビュー依頼の不足と版/未決を見える形で扱う。戻りや待ちを減らせるかは未測定。前回の [C2選定案](discovery-selection.md) は観察対象の選定であり、受付整備の実施合意ではない。
- 根拠：架空の [DEF-IN-v1](definition-intake.md)。前段の WORK-v1 / CASE-v1 / OPTIONS-v1 は [C2選定案](discovery-selection.md) に保持。以下の役の発言は設定で、実本人の回答ではない。

## 境界と現在の仕事

- 現行：受付担当役が依頼と添付を開き、設計書/要件/参照仕様のID・版・未決欄を手で照合する。不足は箇所と理由を設計担当役へ返し、再提出を同じ照合へ戻す。揃えば受付結果をレビュー担当役へ渡す。戻り回数・所要時間・待ちの主因は未取得。
- 目指す振る舞い：受付に必要な情報、照合結果、不足/矛盾/未決、根拠版、返却先を一件ごとに追える。権限者が受付結果を確定してレビュー枠調整へ渡せる。受付と設計承認・実装開始許可を明確に分ける。
- 対象範囲：依頼の受取りから不足の返却・再提出、受付結果案の確認とレビュー担当への受渡しまで。枠の確保、設計内容の承認、実装開始、外部通知/登録は対象外。製品利用者の受注業務、仕様の妥当性判断、方式選定も対象外。
- 開始条件/入力：匿名の架空依頼、設計書・確定要件・参照仕様のID/版/所在、未決欄。終了成果：受付可否と不足/保留理由を示す受付結果または設計担当への返却。受付済みはレビュー可能性の入口で、内容承認ではない。
- 通常例：ID/版/所在と未決欄を照合し、権限者が確認後、受付結果をレビュー担当へ渡す。不足例：不足箇所/理由を設計担当へ返し再提出で再照合。矛盾例：版不明・版矛盾を受付可能としない。未決例：未決を受け付ける権限者と規則が未確認なら保留する。担当不在例：確定やレビューへ進めず、代行権限を確認する。

## 責任・Designへの受渡し

- 提案：受付担当役が照合/返却/受付結果案を作る想定。確定：権限を持つ人に限るが実任命は未確認。実行：設計担当役が不足を修正して再提出する想定。レビュー：レビュー担当役が版/未決/根拠を確認する想定。設計内容の承認、レビュー枠確保、実装開始は別判断。AIや通常ツールには確定権限を与えていない。
- Designへの問い：必須欄と正本/版を誰が維持するか。定型欄・ID/版照合を人/既存チェック表/通常ツールのどれで支えるか。自由記述の未決と根拠対応にAI補助の理由と検証条件があるか。結果と返却履歴をどう保持/提示するか。外部通知/登録の許可は別途どう確認するか。
- 未解決と停止点：A01–A05、P01/P02の未確認が該当受付判定/確定/受渡しを止める。資料項目の整理、匿名の例の作成、比較条件の設計は進められる。P03が未決の間は効果・改善幅を主張しない。
- 次の受渡し：受付担当/設計担当/レビュー担当と業務決定者に通常・不足・矛盾・未決・不在の例を示し、役の発言設定、必須資料、権限、閲覧可否を訂正してもらう。その後、同じIDでDesignと必要なら限定試行へ渡す。[別条件C/D](definition-forward.md) は変更時の再確認案。
