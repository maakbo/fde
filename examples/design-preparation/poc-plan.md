## 今回の対象と事前条件

今回減らす不確実性は「形式と限定的な入力対応を通った候補を、確認対象の同一性を保って pending_review に留め、演習の採用・訂正・拒否へ安全に遷移できるか」。試作品はその仕組みを確かめる成果物であり、現場の利用価値を届ける MVP や許可環境での pilot ではない。実現性を判断する PoC としての結論は実行証拠を得てから出す。

- 入力と版：匿名の架空 JSON、既存の PROMPT-v2/SCHEMA-v2、7入力/出力、検証器、POC-IN-v1、G-v1。実行物のコード版・設定、実行環境の詳細は実施時に記録する。候補と確認は依頼 ID、入力・資料と metadata 版、候補、契約版に結び付ける。
- 許可・対象外：ローカルで架空 JSON を読み、前回出力の再生と別文書への実 AI 適用を明示して分ける。実 AI 接続、実人への連絡、通知・登録・送信、本番操作、費用発生は今回の許可に含まれない。確認役 reviewer-A は演習上の架空役であり、人の認証・同意・実確認を示さない。
- 期待する出力：不正入力・不正候補は採用候補へ進めず、正しい候補も確認前は pending_review。演習の確認記録では use_as_review_draft / return_for_correction / reject と理由を分ける。use_as_review_draft はレビュー資料の下書きに限定する。対象変更で旧確認を失効させ、訂正時は原候補を残し、改訂・再検査・再確認へ戻す。
- 必須ゲート G-v1：G1 入力/構造/根拠対応が不正なら進めない。G2 確認なしは pending_review、許可役割・判断・理由を検査できる。G3 対象のいずれかが変われば旧確認を使えない。G4 訂正と拒否を区別し、原記録を保持して訂正後は再検査・確認する。G5 使用はレビュー下書きまで。本文の「承認済み」等を権限の根拠にせず、送信/登録機能を作らない。どれか一つの重大な不通過を他の件数や速度で相殺しない。
- 評価者・判定：機械照合は形式/限定的な入力対応のみ。意味・根拠の適格性、実際の受付権限は独立した人の確認が必要だが、今回の実確認者は未特定。演習の reviewer-A の記録を実確認に換算しない。G-v1 は演習条件で、実際の正本/版、受付権限、未決可否についての合意済み条件ではない。
- 評価集合と事前期待：BASE-v1 は前回の7入力/出力を再生用とし、今回の実モデル生成結果に算入しない。試作の通常・不正/不足/矛盾・権限/対象変更を G-v1 に対応させる。C は別条件として metadata 版だけの変更を隔離し、候補本文と依頼 ID は保つ。D/E は次工程の判断用の別条件であり、試作の合格件数には加えない。具体的な試作ケース件数/分母はケース選定時に確定し、前回の7件をそのまま今回の分母にしない。
- 調整と別条件：最初の試作の失敗から必要な最小修正は最大1回。同じ条件で退行を確認し、未調整の C のような別条件で再試行する。評価ケースに合わせて指示を調整した例だけから一般化を主張しない。修正箇所、理由、版、保持した条件を記録する。
- 独立照合：試作の生成・実装担当とは別の照合担当が、事前期待と実出力/状態遷移を比べる。担当者は未特定。機械で確認できる構造/対象結合と、人が確認すべき意味/権限を別の結果として残す。
- 上限と停止：反復は初回＋必要な修正1回とその再試行まで。時間上限は未決、実モデル費用は発生させない。時間上限を決める必要があれば実施前に担当へ確認する。重大な失敗、許可喪失、確認不能、上限到達では使用可能状態への遷移を止め、未解決を返す。成功まで繰り返さない。
- 保存・隔離：入力 ID/版、出力またはエラー、検査結果、確認対象と理由、修正差分、実行環境/許可の実態だけを最小限記録する。匿名の架空入力に限定し、外部接続がないことと保存先・閲覧者・保持/削除方法は実施前に確かめる。ローカルという名称だけで隔離済みとは判定しない。

望む効果は誤った候補の受け渡しを避けること。そのためには確認役が候補と根拠を同じ対象として確認・訂正・拒否できる使われ方が必要で、その前提として G-v1 の品質ゲートが要る。実際の業務効果、利用率、確認時間、負担は未測定。分母、期間、比較対象、実確認者も未定であり、今回の技術試作から逆算した目標値は置かない。
