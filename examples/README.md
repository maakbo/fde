# FDEの実践例

FDEが顧客と何を話し、AIへ何を任せ、どんな成果を確認するかを、架空のシステム開発で追えます。各例には、想定した状況、使った手順、残った成果、検証した範囲を記しています。

## 機能追加を進める

[受注一覧の検索機能追加](field-delivery/order-search/README.md)は、開発チームが要件定義、設計、実装・テスト、レビュー、リリース準備をAIと進める例です。要件・設計・コード・テストを順に確認できます。

[受注一覧のCSV出力追加](field-delivery/csv-export/README.md)は、工程ごとに別のエージェントへ引き継いだ例です。質問と回答、実装者とは別の受入確認、運用担当の受取結果を追えます。

これらは、開発チームの仕事へAIを取り入れる例です。製品の利用者がAIエージェントを操作する機能を追加した事例ではありません。

## 設計業務を改善する

[基本設計の下書き支援](design-preparation/README.md)は、エンジニアが要件と関連設計を確認して基本設計をまとめる業務を題材にしています。[相談から改善案を作る過程](design-preparation/practice.md)を読み、必要に応じて知識・情報・委任・評価の具体的な試行へ進めます。

[六つの成果物を引き継ぐ例](design-preparation/standard-handoff/README.md)では、現状の聞取りから試行後の判断まで、同じ条件を成果物に引き継いでいます。

## 業務と環境を理解する

- [システム開発の仕事](system-development/README.md)：人手によるウォーターフォール型開発のAs-is。要件定義から運用・保守までの10工程と、作業・成果物・受渡し・差戻しを確認できます。AI導入先は未選定です。
- [人とAIの作業環境](human-agent-workspace/README.md)：人、端末、AI、GitHubの関係。

架空の担当者回答、実際に実行したコードや確認、未測定の現場効果は、各例で区別しています。
