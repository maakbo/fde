# 架空の開発チームからの相談

受注管理システムの開発チーム。SEが利用者へ聞いて要件・設計を作り、開発者が実装し、
別の担当がレビューと受入条件の確認をする。運用担当へは変更点と確認/戻し方を渡す。
今回、営業担当から「受注一覧の検索結果をCSVでもらい、手元で確認したい」と依頼が来た。
既存の一覧には状況と受注日の検索がある。CSV出力はまだない。

開発チームは設計書を渡しているが、実装者が条件の細部を補ってしまい、レビューで
聞き直すことがある。AIをコード作成にだけ使うより、要件・設計・実装・テストの
受渡しをつなげて、次の担当が判断できる状態にしたい。
ただしAIによってレビュー量や確認負担が増えるのは困る。
現行の工数・件数・待ち時間のbaselineはまだ測っていない。

この相談と担当者の回答は全て架空。実会社や顧客の情報を扱わない。
許可は公開の架空資料、ローカル下書きとコード/テスト実行、localhost通信だけ。
外部送信、費用追加、実データ、GitHub操作、merge、本番配備は委任しない。
実組織の開始・承認・定着・効果を確認したとは言わない。

役割名は演習上の担当であり、実在の担当者の同意ではない。
不明な業務仕様は質問として返し、推測で決定しない。
