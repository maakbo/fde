# 進行役からDiscoveryへの確認・修正依頼

架空のSE・開発責任者役として答える。実組織の承認ではない。
今回の目的は開発チームの受渡しを改善すること。その検証題材としてCSV機能追加を
要件→設計→コード→独立受入→リリース準備まで、許可されたローカルで通したい。
CSV詳細をDiscoveryで決めないのは妥当だが、「次工程で決めること」と「案件の対象外」を
分けてほしい。CSVを作ることまで別件・対象外にすると、この試行が途中で閉じてしまう。

期待する改善仮説: 条件と根拠、未決定、確認者を同じ記録へ残し、後工程が要件を補完せず
質問・実装・検証を返せる。最大ボトルネックや削減効果は未測定のまま。
現在の架空メモにはCSVの列名と文字コードと0件時の扱いがなく、実装者が推測し得る。
SE役がDefinitionの質問に答える。利用者は検索結果を手元で確認するためCSVを希望。
作業者はSE、実装者、独立確認役、運用受取者という演習上の役割。コードの採否と
リリースは人が判断、今回はその材料とローカル実行まで。正式導入はしない。

追加調査: Skillで使うtemplateが見つからなかった場合、実際に確認した絶対pathと
Skill内の表記を返してほしい。rootが最も近いSkillの導線を直す。
