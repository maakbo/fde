# 業務で試す — 仕事の構造を対話からモデルにする

[試作モデルを見る](README.md) / [fdeの既存モデリングSkill](../../../.agents/skills/business-context-modeling/SKILL.md)

## どう使うか

初回から要件定義書や全業務一覧を用意する必要はありません。現場の仕事を普段の言葉で短く話し、AIエージェントに仮モデルを作ってもらい、関係者と一緒に訂正します。図が完成したら終わりではなく、業務の境界・責任・情報を合意し、改善や実装の判断に使うことが目的です。

**機密保護**：会社の実資料、顧客名、個人情報、非公開設計は、許可されていないAI・GitHub・公開リポジトリへ入力しないでください。実案件を扱う場合は、会社の承認された環境でこの手順を使い、成果物も社内の承認された保存先に置いてください。公開fdeの架空例へ業務データを追記しません。

## Codex / AIエージェントへの開始依頼

下をそのまま会話の開始に使えます。組織・業務の具体がまだ曖昧な時ほど、未確認のまま作り込まず、仮モデルを先に出して対話してください。

> fdeの `.agents/skills/business-context-modeling/SKILL.md` と `.agents/skills/business-flow-facilitation/SKILL.md`、`examples/system-development/rdra-preview/` を参照して、私の仕事をRDRA型の一連のモデルにしてください。目的は、関係者と仕事・業務・作業の理解を共有し、改善対象を議論することです。
>
> 最初に私の説明から、分かっている事実／仮説／未確認を分け、**システムコンテキスト図（仕事の目的・背景・対象・境界・関係者・外部システム）**の仮案を返してください。情報不足で止まるより、確認すべき点を残して対話を始めてください。質問は一度に一つ、すでに答えたことは聞き直さないでください。
>
> 次に、**ビジネスコンテキスト図（主な業務・関係者・外部システム・情報）→ビジネスユースケース図（選んだ業務の子業務）→業務フロー図（担当者ごとの本当のスイムレーン、上から下の時系列）**へ展開し、**情報モデル（概念・意味・関係）**を横断的に保ってください。図と図を安定ID、親子関係、情報の参照でつないでください。
>
> フェーズ・工程は業務へアクセスする索引として使い、業務と同一視しないでください。意味上の分解は「仕事→業務→子業務→作業」です。図の分かりやすさのために情報や役割を捏造しないでください。子の発見は親や情報モデルへ戻してください。
>
> まず**As-Is**から始め、具体的な一件をたどって確認してください。現行の業務にAIを使っていると決めつけないでください。To-Beの改善やAIへの委任は、現状を確認した後に別モデルとして扱ってください。
>
> 成果物は**Markdown内のMermaid**を正本にして、親子のリンクと短い説明を付けてください。作業中のモデルは合意済みと見なさず、事実・仮説・未確認を保持してください。公開範囲を確認するまで、実案件の内容を公開リポジトリへ書かないでください。大規模な既存ファイル差替えは承認を取ってください。

## 最初の会話で伝えること

- **どんな仕事か**：例「顧客の要望から業務システムを開発して届ける」。
- **誰のため、なぜ必要か**：例「申請・承認を業務で使えるようにしたい」。
- **どこからどこまでか**：例「開発依頼を受けてから運用保守まで」。
- **何を扱うか**：例「要求・要件・設計・コード・テスト結果・変更」。
- **まず掘り下げたい場面**：例「基本設計のレビュー時」。

これは記入フォームではありません。分かるところから普通の会話で始め、AI側が不足分を必要な時だけ一つずつ確認します。

## 初回に受け取りたい成果

| 段階 | 見て判断すること | 完了と見なさないこと |
| --- | --- | --- |
| ① システムコンテキスト | 仕事の目的・背景・価値、誰と何に関わり、何が対象外かが一目で読める | 目的を本文だけに書き、図が参加者一覧で終わる |
| ② ビジネスコンテキスト | 主要業務、情報の作成・参照・受渡し、関係者/外部システムの関係が読める | 工程名の時系列だけ |
| ③ ビジネスユースケース | 親業務が子業務へ分解され、責任・成果・情報がつながる | 「実装→レビュー→完了」のような汎用手順を業務と呼ぶ |
| ④ 業務フロー | アクターごとにスイムレーンが分かれ、順番、判断、戻り、引渡しが明確 | アクターを注記しただけの一列のフロー |
| ⑤ 情報モデル | 用語の意味、同一ID、概念間の関連が一貫している | 文書名・成果物の直列一覧 |

5種類を一度に完璧にせず、**全体像の仮説→具体的な一業務→関係者の訂正→親へ反映**の往復を一周させて使えるか確かめます。

## 現状と制限

このディレクトリは**試作**です。会社の業務での実運用、社内環境でのMermaid描画、関係者合意、図間の自動整合チェック、AIエージェントによる端から端までの反復実行は未検証です。業務利用の実績や完成したアプリと呼びません。Mermaidの `swimlane-beta` はバージョン依存のため、対応エディタでの確認が必要です。
